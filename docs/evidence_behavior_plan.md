# 证据分类与实际生成行为实验计划

本计划于 2026-10-09 固定。模型为本地 Qwen2.5-3B-Instruct；使用现有 kba-rag 环境和 GPU 0。
当前 300 条测试实例已经查看，定位为诊断集；任何指令修改、阈值或超参数选择只在验证集进行。
首要交付物是四种分类条件的结果表、各类混淆矩阵和可靠性审计。随后独立研究前生成信号与自由回答行为。

## 第一阶段：四条件分类对照

| 条件 | 格式 | 输出预算 | 处理 |
| --- | --- | ---: | --- |
| plain8 | 原纯文本 | 8 | test 复用已有 300 条原始输出；val 新生成 |
| plain64 | 原纯文本 | 64 | 新生成 |
| chat8 | 官方原生 chat template | 8 | 新生成 |
| chat64 | 官方原生 chat template | 64 | 新生成 |

四组使用相同问题、完整五篇文档、文档顺序和分类指令，不重采样、不裁剪证据。
现有“只输出一个类别词”的指令保持原文，它也约束首行为类别。
chat 把该指令放在显式 system 消息，文档及问题放在 user 消息。
调用本地 tokenizer.apply_chat_template(..., add_generation_prompt=True)，分词时不重复添加特殊 token。
其余配置固定为 BF16、SDPA、单样本、greedy、单 beam、use_cache=True、logits_to_keep=1。

解析在新推理前固定：

- 严格格式：整个输出是单个 answer/refuse/conflict；容忍大小写、首尾空白及末尾句号/感叹号。
- 首行解析：首个非空行是上述单个类别词，解释不参与分类；首行多个类别或首行解释文字保持 invalid。
- 分类指标采用首行解析，invalid 保留在全部实例分母和对应类别的假负例中。
- plain8/test 的首行解析保留“历史事后分析”标记；不覆写原始结果。

默认先跑 val 95 底题/285 实例，再跑 test 100 底题/300 实例。
全套新增生成次数为 4×285 + 3×300 = 2,040；旧 plain8/test 复用。
只是格式与预算对照，不根据当前 test 结果挑选或修改指令。

## 第二阶段：分类诊断与可靠性

报告路由器和四种条件的 Accuracy、Macro-F1、三分类错误可答判定率、严格格式通过率、首行可解析率，
并逐类报告 Precision、Recall、F1、Support 和 3×4 混淆矩阵（最后一列为 invalid）。
分别记录 Refuse→Answer 和 Conflict→Answer 的次数以及各自类内比例。
三分类错误可答判定率不等于自由回答中的缺证回答率。

按 original_id 对齐，保留一个底题的三种证据配置进行 10,000 次配对 bootstrap。
预设对照为四种条件各自减路由器，plain64−plain8、chat64−chat8、chat8−plain8、chat64−plain64。
输出准确率、Macro-F1、三分类错误可答判定率、各类召回率和两种错误可答判定率的差值区间。
区间不包含重新训练探针的随机性。

audit.json 检查现有特征哈希、形状、ID/标签顺序、NaN/Inf、零向量、完整发布数据的跨集合 ID 和问题文本重叠。
记录最佳层仅按验证准确率选择、C=1/lbfgs/max_iter=2000 为预设配置、标准化仅拟合 train、sigmoid 仅拟合 val。
历史失败尝试若无日志不能追溯；完整特征缓存不能用零向量代替失败。
原路由器的 val 预测来自已经在 val 上校准的模型，因此报告注明校准内评估，不当成独立测试结果。

剩余 380 个未纳入本轮实验的测试底题（1,140 实例）只保存 ID 清单，不生成预测。
确认实验在设置冻结后另行设计；本轮不消耗该集合。

## 第三阶段：自由回答与前生成探针

固定自由回答指令：仅依据提供文档；证据不足时说明不足、不猜测；相关证据冲突时报告冲突、不选边；
充分时给有依据的短答。预算 128 tokens，分别运行 plain 和 chat，其他解码设置相同。
这些指令不同于分类指令，也不同于旧 P0，因此两个格式都重新训练同模板探针。

每个格式依次：

1. 在相同 train 600、val 285 实例上提取自由回答提示的最后 token、所有解码层状态。
2. 每层拟合 StandardScaler + LogisticRegression（C=1），仅按 val 准确率选层，val 上 sigmoid 校准。
3. 在当前 test 300 实例上生成短答；首次 prefill 内捕获同定义状态、在首个生成 logits 前计算探针结果。
4. 保存探针类别、概率、层号、特征文件及校验值、原始回答和长度/截断记录。

探针结果不反馈给生成器，不实施干预。钩子只保存最后位置，不保存全部提示位置状态。
前 L−1 层读取解码层输出，末层读取最终 norm 输出，对齐 HF hidden_states[1:]；已用小型 Qwen2 CPU 模型检验。
模型参数冻结；训练/验证只提取状态，不需要生成答案。

## 第四阶段：行为标注与统计

生成结束会导出离线 HTML 盲审页，隐藏真实类别、探针预测及格式条件。
显示问题、可展开的五篇文档和原始生成，标注五个独立字段：

| 字段 | 含义 |
| --- | --- |
| has_substantive_answer | 是否给具体实质答案，包括承认不足后的猜测 |
| acknowledges_insufficiency | 是否明确说明提供证据不足 |
| acknowledges_conflict | 是否明确报告相关证据冲突 |
| selects_single_answer | 是否选定一个答案；列出冲突候选且不选边不算 |
| answer_correct | 实质答案是否正确且有文档依据 |

每项填写 yes/no/unknown，并记录标注者。空输出、模糊或截断不能自动算拒答。
标注文件携带本批输出的盲审清单哈希，拒绝来自其他输出批次的标签。
代码不以真实标签、探针结果或字符串关键词自动决定模型是否实际拒答。
若采用第二位标注者复核，先保留独立标注再记录最终裁定。

核心数量为 N_R（全部缺证）、N_RR（其中探针判缺证）、N_RRA（其中随后实质作答）。
同时报告全部缺证的回答率、N_RRA/N_RR、N_RRA/N_R，以及探针未判缺证组的回答率。
冲突类单独报告全部冲突的选边率、探针判冲突后的选边率和明确报告冲突的比例。
充分类报告有依据的正确回答率、不作实质回答率及明确以信息不足为由拒答的比例。

未审核或不确定项保留完整分母，点估计暂为 null，报告可确定的上下界。
相关标注完整后自动计算按底题 bootstrap 区间，及 chat−plain 的缺证回答率/冲突选边率配对差。
这些是关联结果，不能直接证明模型“知道却故意不执行”。

## 执行顺序与停止点

先执行分类 smoke，再运行完整四条件并检查分类型结果。
完成后运行自由回答 smoke，再运行两个格式的完整提取、训练和生成流程。
行为审核完成前，不把生成结束的初步报告当作最终行为结论。
两阶段都逐实例保存，可中断续跑；模型/提示/代码/数据变更须使用新 run_dir。

如果 chat 明显改善分类与行为，首先考虑输入/指令解释。
若同模板信号在验证及确认集稳定可读，而实际行为仍失配，再设计局部 patching、一般拒答偏置、随机/同类替换控制，
同时记录充分证据下的错误拒答代价。本轮不自动启动干预、扩大模型或确认集实验。
