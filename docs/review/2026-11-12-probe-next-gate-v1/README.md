# 冻结 probe 后续：增量、参照与确认路径的门禁判断

2026-11-12，Asia/Shanghai。应用户要求按顺序推进后续步骤。本次使用既有已归档证据、重放绑定复评核验；外部文献检索请求连接失败，未完成新的文献核查。本报告为研究决策，不是采集协议。

## 决定

**保留限定配置的阶段结果，暂不进入确认协议或 v2 GPU 运行。** v2 实际复评改善了材料的可追溯性，但尚无新证据使第一阶段的两项条件——实质增量和可执行的确认路径——同时成立。这里的停止是执行既定条件，不是证明研究不可能，也不把研究问题本身视为无意义。

## 1. 可证伪问题与具体增量

固定 Qwen2.5-3B-Instruct、P0 chat、末提示 token、零基 L28 和既有标准化/线性/校准/argmax。候选问题：在预先限定的五文档分布、可审计状态及表达关系参照下，同一底题的 S/I/C 两表达，固定读出是否达到用途所需的双端参照一致性？按底题分别报告每状态双端符合、一端符合、双端不符、翻转及 unknown/失败覆盖；状态变化的连续分数方向单列。稳定但两端错误不算成功。若适当参照和抽样成立、预定容差未达，则该配置在限定用途不成立；若达到，则仅支持该范围，不能推出其他读出或隐藏状态的信息量。容差和总体尚未确定，以上不是预注册端点或协议。

潜在价值是把方向响应、类别正确和表达稳定放在相同底题与同一固定读出下区分；仅观察某个旧 probe 在人工模板上失效，仍不足以建立一般贡献。根据[已归档的逐篇原文核查](../2026-11-11-phase-one-research-gate-v1/README.md)，KBA 已有同题三状态和提示稳健性，ContextConflict 已有配对冲突 probe，Hidden Commitment 已有顺序和改写一致控制；[ESB 核查](../2026-11-11-reference-budget-increment-v1/README.md)还显示证据梯度行为评估已有近邻。候选的联合评测组合是具体差异，但这些部件分别已有先例，所查章节未发现等价组合不证明不存在或具有足够论文价值。**实质增量尚未成立**；本次网络失败，也无法称已做最新或系统性综述。

## 2. v2 可以回答与不能回答什么

[v2 草案](../2026-11-11-binding-repetition-control-draft-v2/README.md)有6个已暴露底题，S→C和S→I各12对完整提示等 token；S/C对应槽去重词集合相同。作者及一个 CLI 会话的36状态、24个S/C值和18表达对一致；本轮只读重放 [verify_review.py](../2026-11-11-binding-review-v1/verify_review.py)，退出0，180+108处引用核验通过。一次会话及其后续配对不构成两个独立评审；字面引用、封存和状态一致不认证语义真值或完整私有上下文。

v2 尚无 probe 输出。即使未来运行，只能描述这六题在新构造上的读出：S/C控制了长度与去重词集合，但词频、赋值关系、位置等仍变；S/I对象名有系统差异。旧材料与v2还同时改变多个设计因素，所以跨版本变化本身也不能识别重复度的因果效应。若将来另立开发目标，需先明确要排除的解释与实际可判别的对照；当前不借确认研究之名自动建立该运行。

## 3. 参照、用途及资源

| 前置项 | 可核实的现状 | 决定 |
| --- | --- | --- |
| 语义参照 | 作者知情；v2有一位外部CLI的可追溯判断，未认证独立错误或完整上下文。 | 足以支持探索性材料审查，不是正式独立金标准；正式批准仍0。 |
| 用途及容差 | 候选为限定分布上的三状态测量，尚无实际使用者接受的失配、覆盖或置信精度要求。 | 不能根据旧结果设门槛；此前90%及39/80底题仅是特定假设的数学示意。 |
| 资源 | 已有一次CLI完成的证据，无法从累计usage推断价格、后续额度或独立性；无已落实评审者、决定者、工时及预算。 | 无法保证确认审核覆盖和分歧处理；用户无需本人逐条评审。 |
| 未知与失败 | 原材料可保留unknown；完整覆盖及有效参照比例尚无预定要求。 | 未知不能事后删除或视为成功；须在任何未来协议前明确分母和处置。 |

这些缺口需要实际的新来源、资源或用途决定，不能通过更换CLI会话、随机编号或重复既有评审自行闭合。过去实际CLI复评不重跑。

## 5. 后续及边界

只有在具体研究增量与可执行确认路径均有新证据成立后，才另立候选协议，事先固定分布、独立参照、底题单位、unknown/失败、用途容差、资源和停止条件并审门禁。若明确提出另一个有限开发目标，也须单独审查其价值、执行边界及运行器，不能将其当作确认或沿用旧放行。必要GPU由用户运行；当前没有GPU命令。
