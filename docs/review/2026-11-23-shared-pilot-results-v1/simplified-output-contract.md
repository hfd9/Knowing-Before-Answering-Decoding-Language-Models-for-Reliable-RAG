# 两道工程题的简化输出约定草案

2026-11-23，供下一版两题工程验证。现有逐题诊断见[错误表](../../records/2026-11-23-shared-pilot-error-table.md)。

### 输入与证据定位

三条路线使用同一份题面、两来源和规则。预处理仅在原文的来源句前加 `S1`、`S2`，在类别题每个代码的完整规则行前加 `R1`、`R2`。编号按来源、规则各自的原文顺序生成。保存编号到原文字节跨度的映射，编号本身不含正确标签且不改变句子内容。生成过程只使用公有材料和实际抽取。联合和分支继续共享一次真实抽取，沿用既有抽取解析器。强直接从原材料自主找出两个候选。分支每次只收到一个实际抽取候选作为假设。

### 输出格式

每行只留一个字段，使用 ASCII 大写标签和半角符号。直接与联合统一输出两条世界行和一条最终行，顺序为世界行、世界行、最终行。分支每次只输出一条相同的世界行，由评分器合并两个分支并记录最终标签。

| 行 | 格式 | 约束 |
| --- | --- | --- |
| 世界 | `W=<值>\|<Y或N>\|<证据ID列表>` | 值使用现有整数或标识符规范。数值写 `34`，单位留在题面。证据 ID 按逗号分隔，允许用 `-` 表示无证据。 |
| 最终 | `F=<Y、N或U>` | 两世界同 Y 则 Y，同 N 则 N，两世界异答则 U。 |

以下是“是否超过 30”的合成正确示例，用于 CPU 测试。

```text
W=34|Y|S1
W=58|Y|S2
F=Y
```

以下是“是否适合干燥运输”的合成正确示例。

```text
W=VX3|Y|S1,R1
W=LM7|N|S2,R2
F=U
```

联合和直接的两条世界行可交换，按值连接。分支的值必须与该次实际假设一致。解析器接受 LF 或 CRLF 与一个可选的末尾换行，其他内容严格按行匹配。重复世界、重复证据 ID、额外行、错标签或无法解析的字段计格式失败。证据 ID 的语法为 `[A-Z][1-9][0-9]*`，未知但语法有效的 ID 计证据失败。下游输出的候选值和实际抽取不符计候选绑定失败，保留原值及原标签。技术失败、无效抽取导致的跳过、缺分支及格式失败均留在计划分母。`U` 表示世界异答，与技术或格式未解决分别统计。

### 评分与比较

1. 首先分别保留可读取状态、候选绑定、实际输出的最终标签、按世界行合成的标签，以及最终标签是否与合成一致。直接和联合保留原最终标签供比较，分支按固定规则合成。
2. 独立检查每个世界的答对情况及证据。数值世界须定位到自己的来源，并与问题中的阈值和单位共同支持该答案。类别世界须同时定位到自己的来源与对应代码规则。未知、错世界、无关或遗漏的 ID 计证据失败。有效 ID 如果支持相反标签，记为证据反驳。错误回答引用正确来源时，两个问题分别计数。
3. 正确有据要求两个世界、最终标签、合并一致性及证据全部成立。按底题配对，分别报告同答问题正确有据、异答问题的 Y/N 及是否有据、未解决、调用数、输入输出 token 和时延。联合和分支的路线成本各含一次共享抽取，对照实际执行只支付一次该抽取。
4. 两道工程题在三条路线均完整可读、证据能核验且判断错误可定位后，再决定其余十题是否值得运行。“效果接近”应在下一批运行前写明可接受的配对损失和异答风险，不能根据结果回填。联合达到这些条件且成本更低时才优先。

### 可选的程序比较基线

若新格式下仍反复出现数值判断错误，单列“共享抽取 + 程序比较”诊断。仅使用实际抽取的两个规范数值和原问题，精确抽取受支持的“超过 / 低于”谓词、比较阈值和单位。定位来源值和单位做一致性检查，缺字段、歧义、量纲不一致或候选与可见来源无法对应时输出未解决。按两个关系式计算 Y/N，再按相同规则合并。参考答案只在最终评分连接。类别规则另行设计。这个基线衡量固定数值题型上的额外模型调用价值。

### 本轮 CPU 检查

基于两题的六个原问题、实际抽取值及已知参照做内存检查。18 个合成正例及 13 个负例和边界检查通过，覆盖行解析、来源与规则原文定位、两世界匹配、合并冲突、错误判断、证据缺失、错 ID、错候选和语法失败。测试中复现了 34 支判 N 时直接与联合可以同时出现最终 Y 和合并冲突，分支则合成 U。这个检查使用知情参照构造测试预期。生产解析器及新格式的真实模型输出留待下一轮验证。
