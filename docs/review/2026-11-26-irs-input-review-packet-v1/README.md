# 两组 IRS 候选：输入优先复核准备包

状态：`prepared_not_reviewed`。用户提出先对已有三态结果做复核，再决定是否扩样；两组均已被作者选出并看过输出，且共享一条规则。本包不创造独立规则、不取得独立法律评审，也不自动联系任何人。

## 文件与信息边界

- [仅输入的复核目录](public/README.md)：包含从既有 7B 直接路线归档复制的六条完整 system/user 输入、六个协调 ID 和空白表格；不包含作者参照、模型回答、原评分或 same／different 标签。六条按 ID 排序，原题目中仍可看出金额、日期与来源。
- `coordination/mapping.json`：将协调 ID 与原任务、输入哈希及模型输出哈希对应；**不交给第一阶段评审者**。本仓库已有公开历史结果，技术上无法保证评审者没有接触其他文件；应通过合适的人、会话或渠道实际管理暴露，而不能把换 ID 当作隔离证明。
- [构造与重放脚本](../../../scripts/answer_change_irs_independent_packet.py)：绑定既有 52 文件归档与 run seal 的已记录 SHA-256，核对 24 条原任务及六条选取；生成文件不得覆盖，`--verify` 重建比较。
- [两阶段接收脚本](../../../scripts/answer_change_irs_review_intake.py)：`seal` 只读输入包、空白模板和外部提供的评审结果，先核对字段、日期、逐字支持片段和暴露自述并封存原始字节；`connect` 复核封存后才读取协调映射与模型输出，生成供第二阶段查看的六条输出。评审提交或第二阶段文件不会自动提交 Git。
- [第二阶段接收脚本](../../../scripts/answer_change_irs_stage2_intake.py)：复验第一阶段封存、来源归档与逐条回答哈希，再生成模板并可封存实际收到的第二阶段评审；详见[审阅指南](stage2-review-guide.md)。只核对结构和字面引文，不认证语义、独立性或未暴露，也不是第三方签名。

自动检查只证明文件绑定和引文是输入中的连续文字，**不证明完整阅读、判断正确、评审者未暴露或具备法律能力**；`independence_certified` 固定为 false。允许评审自报已经见过输出或其他暴露，不能因此包装成独立盲评；未知和分歧都要保留。阶段一只判任务中可由材料推出的结论，不能替代核查原始法规版本、适用范围与法律复核。另应记录谁看过两金额和多个日期；这六个输入共享一条 IRS 规则，仍不是六条独立规则。

## 以后有合适复核资源时

将 `public/` 内容单独提供给具备适当判断能力且如实披露暴露的人；不用用户本人逐题审核。对方只看输入填写表格，提供自己对两个日期的结论、原文及元数据依赖，再把表格保存为一个 JSON 文件。只有在实际收到文件后，协调者才运行：

```sh
python3 scripts/answer_change_irs_review_intake.py seal /path/to/completed-review.json
python3 scripts/answer_change_irs_review_intake.py connect
```

路径由实际收到的文件替换；本次没有这份文件，也没有执行以上命令。第二条命令输出在忽略的 `runs/answer-change-irs-review-intake-v1/stage2.json`，其中包括原始输出和空白行为标注字段；应保留封存和完整原始提交。若出错或目录已存在，先检查现场，不覆盖或伪造评审。第二阶段由评审者查看原始输出并记录行为承诺，协调者再与封存的第一阶段判断和既有作者评分比较、保留分歧；第二阶段表格尚无自动语义评分或实际提交。

若合适的独立复核资源暂不可用，继续可独立完成的 v2 材料与评分核对，明确结果仍为知情开发判断；不重复要求用户本人审题，不以一个看过原评分的会话冒充独立评审。是否扩展至 8–12 条仍未决定；未来新规则须在完整协议冻结后选择。
