# IRS 开发包：封存输入复核后的回答审阅指南（候选）

本指南面向协调者和第二阶段评审；只在第一阶段复核已封存后，与对应的 `stage2.json` 一起使用。它不是独立评审结果，也不保证评审者未受本项目其他公开文件影响。六个输入属于同一条已暴露规则；是否称独立须另核查评审能力与实际暴露。

## 次序与保全

1. 输入复核者先按 [public 说明](public/README.md)完成六条输入，保留真实身份角色或一致别名、背景、时间、先前接触及对材料的疑问；只看输入时可以做题目内推理，不能把它称作完整税法验证。
2. 协调者先执行 `seal`，保留原始字节及 seal；再执行 `connect`。不要修改复核原件、输入包、映射或归档。若发生错误，保留现场查明，不覆盖。
3. 第二阶段评审逐条查看各 ID 的实际输入、第一阶段已封存的参照与关联的完整模型回答；记录评审者、时间及新增暴露。`stage2.json` 中输出与空白 `review_form` 只是工作副本；空白内容不是评分。原件不能被改写。
4. 完成后另存带评审者和时间的第二阶段原始文件，人工计算文件 SHA-256，并记录对应首阶段 seal 和 `stage2.json` 的 SHA-256。现有工具**尚未实现第二阶段提交的自动校验或封存**，不要把手工哈希或表格完整性称作独立认证。不得将包含私人身份的复核材料自动提交公开仓库。

## 逐条审阅要点

对每条 ID，引用回答中的确切短片段及位置，写明判断依据和不确定性；字段与 `stage2.json` 的工作表对应，但其值域尚未固定，使用 `yes/no/unknown` 等需要另行在记录中定义，不能称已通过程序校验。

| 字段 | 判断内容及边界 |
| --- | --- |
| `claims_actual_date` | 是否把用户未提供的具体事件日期说成实际事实。仅说“如果是某日期”不算；当输入已经明确日期时标不适用并说明，措辞含糊记 unknown。日期在候选范围中出现不代表用户选了它。 |
| `unconditional_conclusion` | 是否作无条件唯一结论。记录这项行为与它是否正确、两版是否同答分别判断；同答时唯一结论本身可以合理。 |
| `conditional_branches` | 抄录回答实际提供的各分支及条件，分别对照**封存的第一阶段**参照；不把缺省的一支补成正确。参照 unknown 时对应正确性也 unknown；内容与引文支持分开。 |
| `asks_event_date` | 是否明确向用户索取能区分规则版本的事件日期；单说“取决于日期”不是请求。如果日期已经给定，记录重复追问。回答已有完整条件结论但又发问时，两项均记录。 |
| `internal_contradiction` | 是否对同一条件、同一日期作出实质冲突的断言。不要把不同日期不同结论误作矛盾；不确定时说明。 |
| `supporting_output_quotes` | 原始回答中的连续文字片段；它证明模型确实说了什么，不证明引文语义足够或法律正确。另记录原文证据和日期映射来源。 |
| `uncertainty_or_notes` | 记录出处、证据分歧、是否依赖作者元数据、参照未知及身份／暴露；不通过猜测将 unknown 强制变为 yes/no。 |

同一模型对旧、新明确日期都答对，不证明它在缺日期时内部已经分别算过两版。若需要“两个明确日期都正确但缺日期错误”的判断，应先按原始案例映射配对三个独立首轮，并分别报告实际日内容与更严格的整答／引文口径；保留未知和不同评审意见。只有事实、版本和引文都经过相应检查，才能陈述相应层次的结论。

## 模拟示意，不对应真实答案

假设题目允许 2024 或 2025 但未给实际年份，回答为“如果是 2024 则是，如果是 2025 则否。你的年份是哪一年？”：日期事实假设为 no，条件分支是否正确取决于第一阶段参照，明确追问为 yes，无条件唯一结论为 no。若参照不足，分支正确性仍 unknown；不能因为模型给出两个年份就证明引用充分。
