## 改写和接口

[原有未跟踪改写构造器](../../../scripts/query_determinacy_world_paraphrase_material.py)只在内存运行：24个背景（12底题×两形式），每个背景3问；三种写法各8个背景，题型×来源形式×写法各2个背景。24条继承的参考值与旧材料一致；另按题族匹配实际文本中的值、顺序及预期主体、原子代码前提和穷尽/可能性措辞，24/24符合构造预期。这是知情的模板及机械核对，不是独立语义判断，不能证明自然语言语义等价或主体绑定无歧义。写法由底题编号决定，并非同一底题跨三种写法的配对实验。未生成或封存改写材料。

[审计脚本](../../../scripts/query_determinacy_paraphrase_interface_audit.py)把每个改写背景替换进旧的三个问题，用**参考值模拟完美抽取**，而非实际模型输出，检查旧接口接受情况。失败均为原模板不匹配，故一次单独的抽取组件实验不能证明整条流程可用。

新增[候选适配器](../../../scripts/query_determinacy_paraphrase_branch_candidate.py)：只接受本批六个精确的受控句式，严格验证主体、值类型、穷尽句式及原子代码前提，转换为旧接口，再仅使用传入的预测值构造分支。原文中读取的两个值用于验证输入格式，不用来修正模型预测。2项CPU测试覆盖72问题的分支提示与旧输入逐字相同、错误预测值不被替换、重复/非法预测拒绝、穷尽句式被改动时拒绝，以及数字数组被原冻结解析器拒绝和假预测提示不在缓存。最后两项是组件检查，并非改写管线的完整失败传播测试。72条使用参考值只是接口上界测试，不是72条新预测或独立材料。

候选适配器只是封闭模板的代码修复：它依赖从同一来源文本识别主体、两个值和穷尽语句；不能处理任意改写或验证文本声明的真实性。模型可能抽取错误或输出格式不符，未知合法值可能没有缓存。改写语义由同一知情助手设计，尚未独立逐项审查；未评估端到端准确率或计算成本。不能以72/72重建当作泛化能力。
