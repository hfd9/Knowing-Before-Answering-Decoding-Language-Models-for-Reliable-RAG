# 三路线共享抽取：候选开发合同 v1

2026-11-23。范围为虚构两世界、三问题的知情开发探索；本合同不放行GPU，也不修改旧v1/E1-r1门禁或原拟合预算。真值及引用来自知情作者，不能称独立金标准。真实试跑需单独审查本版本、资源、代码和门禁；任何调整均形成新版本，不覆盖旧输出。

## 输入和执行

统一使用同一份背景、同一问题和相同来源范围。题设明示同一实体字段、两值穷尽且均可能；这不是从矛盾来源自然推得的性质。提示不包含底题ID、问题ID、参考值、题型标签或正确答案；背景本身当然可暴露候选、结构和模板，顺序/措辞不同可能影响结果。

- 强直接：从背景自行找两值、分别假设并判断，输出最终Y/N/U和两世界的值、Y/N与原文引用。
- 共享抽取：每个底题执行一次，从原背景抽取JSON数组。受限v2解析器使用预先给定的整数/标识符域；无效、重复或错误值原样留存，禁止用参考补齐。
- 联合：与直接组同一背景和问题，附加唯一一次实际抽取的两值，并明确它们是待检验候选；要求逐世界判断、最终值和原文引用。
- 分支：同一背景与问题，分别附加一个实际抽取的候选，明确是临时假设而非已确认事实；各自输出值、Y/N和原文引用。由评分器按两支同Y、同N、异答合成Y、N、U。

每底题固定先3直接、1抽取，再逐问题执行联合及两分支；不随机顺序，不排除顺序偏差。分支保留完整冲突原文，可能发生假设与原文干扰。强直接和联合各为单次输出，分支为两次；方法信息与提示长度不同，不能仅将差异归因为一个机制。预计两题26个计划槽，12题156个计划槽；一个有效抽取共享给本背景所有问题。

提取格式无效时记录6个后续问题路线的未解决，并在日志中保留9个未调用的联合/分支槽；本底题先前直接组仍在，下一底题可继续。空、截断、异常为技术失败，保存后停止，人工审查前不自动续跑；已写attempt而无record时保留并阻断，不重试或删除。若无未提交attempt且只有已完成有效前缀，可在同锁下续跑；完成后不重跑。固定每次最多512新token、贪心；EOS以实际模型配置为准。生成期间原样保存完整提示、rendered提示、输入/输出token、原始输出、耗时、状态和绑定摘要；跳过槽不调用模型。设备、模型版本和GPU就绪需实际预检，不通过即停止。硬编码门禁目前关闭，未产生真实run。

## 评分、结果和成本

先以锁住的日志重放并封存公开输入、已提交attempt/record及设备预检，再读取独立文件中的知情参照；评分前核对封存摘要和参照摘要。封存必须记录在连接参照之前，但同一操作者控制文件，摘要不构成可信时间戳、盲化或防特权篡改。

逐题分别报告抽取状态和是否匹配参考值、最终Y/N/U、每个世界答案及其正确性、引用是否逐字匹配，以及最终结论是否与两支一致。`correct_and_supported` 要求最终正确、两支均正确、各支引用满足预设精确句、且最终与两支一致；最终正确不掩盖两支都错。数值题每支要求对应来源句，类别题还要求对应完整规则句。该机械规则偏严格：更短但实际充分的引用可能被标为不匹配，匹配本身也不能证明语义充分；应保存原文并另行知情复核，不把其当独立语义认证。错误候选单列，技术/格式/未执行结果保留为未解决，不从分母剔除。异答参照的Y/N为选边线索，是否无依据须另审，不能由单一字符串判定。

每底题三种部署路线分别计调用、输入/输出token及调用耗时之和：直接3，联合为抽取1+联合3，分支为抽取1+分支6；实际跳过和失败单列，未执行槽不算调用。共享抽取在每种部署路线中各计一次，不能把跨路线合计当单路线成本。调用耗时和不是完整部署端到端墙钟或设备独占证明；还应另报实际端到端时间及环境。三问按底题配对，按同答/异答分层汇报。

## 预先指定的开发筛选规则

这里只固定供开发诊断使用的保守规则，不声称用户已接受应用风险容差：若任一路线/题存在未评分或路线成本不完整，输出“无结论”。否则，候选路线至少要有一题`correct_and_supported`，在每个配对问题上的这一结果均不低于另外两条路线，不能比任何另一条路线新增异答参照上的Y/N选边，而且总输入加输出token严格少于另外两条路线，才将其标记为唯一开发候选；其余均为“无结论”。最低一题只是防止全错时选择最便宜路线，不是可接受准确率。所有判断只针对实际纳入且预先确定的开发题，保留分歧和失败；规则不证明自然分布安全或方法总体优劣，也不等于论文确认通过。

## 当前审查限制

代码封存、锁和哈希可检出部分意外改变，但不能证明操作系统隔离、独立评审、预测期间未读其他资料、时戳可信或抗有权限者更改。模型适配器尚未真实GPU执行；真实token长度检查使用知情参考值模拟抽取而非模型输出，实际输入仍须在运行时校验。实时GPU状态、进程隔离、内存余量和耗时未实测；设备一次性检查不是独占预留。开放新门禁前需审阅运行器及测试、材料用途与参照、输出与评分合同、实际资源预算和不可恢复失败处置，再由用户执行；没有通过时继续停止。
