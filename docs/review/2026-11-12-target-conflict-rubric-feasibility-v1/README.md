# 非目标冲突行为：评分口径与可行性核查

2026-11-12，Asia/Shanghai。用户要求按评分口径→近邻→材料与参照推进。本文是可讨论、可审查的**评分口径候选**及可行性结果，不是已冻结的采集/确认协议；没有新实验题或新模型回答。

## 当前决定

行为问题可明确定义，评分字段可区分目标正确、冲突归属与解释错误。定向查到更直接的[Wang等，COLM 2024](https://arxiv.org/html/2310.00935v3)问答范围冲突检测先例，故**不能以首次按问题范围区分冲突为创新**；其研究单篇上下文与模型参数知识之间冲突，本候选关注两个外部来源及目标可答情形，潜在差异是否有实质研究价值仍未成立。合法未暴露材料、独立参照和实际资源尚未落实，因此不进入确认协议、采集或GPU。

## 1. 评分前提

首选候选用途：用户只要求根据所给记录回答目标字段。目标范围须明确实体、字段、时间、必要的量纲/别名及可信来源规则；非目标事实不能通过排他约束改变目标答案。生成前应有可审计的目标唯一值与来源证据、其他对象是否冲突及对应来源；若冲突可由时间/版本/来源优先级消解，按预定范围判定，不能只凭不同字符串判断。参考状态或问题本身含糊，**参考状态unknown，不作为确定S类**；应保留并单独报告。文档内支持是相对输入的支持，不认证世界真值。

默认输入至少区分：S0目标充分且其他记录不冲突；SO目标充分且另一对象同一字段冲突；CT目标字段真实冲突。S0/SO的比较只在目标问题、目标依据和预期答案实质不变且非目标差异被事先检查时解释；其他格式、长度、位置、重复仍需实测与披露。这里给出状态定义，**未选定材料、样本量或已批准的对照**。

## 2. 单条回答的原始字段

先保存完整输入及完整输出并逐主张拆分；记录相关原文、来源位置和评审者暴露，不能只按词语匹配。字段分别判断，不从一个字段自动猜另一个。技术失败、缺失、空输出和截断另记技术状态，不能当拒答或正确结果；`unknown`是已读但实质含糊，`unreviewed`是未评分，`not_applicable`只用于该输入或字段没有可评价对象。

| 字段 | 取值和规则 |
| --- | --- |
| 目标最终答案 A | 对S0/SO：`grounded_correct`给出唯一受支持目标值且无未撤回互斥选值；`wrong_or_unsupported`给出不被支持/错误目标值或多值且未撤回；`no_answer`明确拒答/只说无法确定；`unknown`最终立场、范围或引用关系不能判断。若CT目标本就无唯一值，此字段`not_applicable`，另单列冲突识别及无依据选边。 |
| 目标冲突声称 T | `yes`明确将互斥记录归于目标字段或目标答案；`no`没有这一未撤回声称，包括只准确说明其他对象冲突；`unknown`泛称“有冲突”但无法判断是否指目标、指代模糊、前后立场不清。CT中T=yes可能正确，SO中T=yes是错误归属；不把全局词频当语义判断。 |
| 非目标冲突说明 O | 对SO且参照确认存在非目标冲突：`accurate`正确明确指出所涉其他对象/字段及冲突且无未撤回错误归属；`inaccurate`明确把非目标冲突说成错误实体、字段或事实；`none`没有提出该说明；`unknown`泛称或归属/最终立场含糊。若S0无真实非目标冲突，单列无据非目标冲突主张，并记此正确信息项`not_applicable`，不得将无据冲突记为none。 |
| 其他实质主张 X | `supported_or_none`无额外实质主张，或所有可评价额外主张均受文档支持；`unsupported_or_contradicted`任一未撤回主张缺依据或受反证；`unknown`范围/依据不能判。目标答案与冲突归属在各自字段保留；不可只看关键词或引用字面位置。 |
| 技术与复核 | 分开记录complete、empty、truncated、failed、missing；评审状态reviewed/unreviewed，引用及不确定理由。只有完整可读且已评分条目可填上述行为字段；空/失败不可当no_answer。 |

准确补充不相关冲突本身并非错误；遗漏该补充在“只回答目标”的用途不扣分。若改成“必须报告所有冲突”的用途，`O=none`的判定需另立标准，不可将两个用途混为一谈。含推测、已撤回结论、源引他人而不采纳、歧义代词及最终不一致均需结合全文，保留证据并按规则unknown；不推测模型意图。

## 3. 候选整体结果与例子

对参考确定且S0/SO目标唯一的完整回答，候选整体成功 U 要求 A=`grounded_correct`、T=`no`、X=`supported_or_none`、且O不为`inaccurate`或`unknown`；O=`accurate`或`none`均可。若已确定A是错误/无依据或明确拒答、T=yes、X明确无据/矛盾，或O=inaccurate，则U=`no`；其余有unknown时U=`unknown`。未复核或技术失败则U=`unreviewed/technical_failure`，不合并进no或unknown。此三值逻辑只适用于**参考确定S0/SO且只要求目标回答**，不是CT端点或正式通过门槛。

假设输入参照为目标唯一值x、其他对象真实冲突：

| 输出的抽象片段（评分规则示意，不是实验题） | A | T | O | U |
| --- | --- | --- | --- | --- |
| “目标是x。” | 正确有据 | no | none | yes，假定无其他主张 |
| “目标是x；另一对象的两条记录不一致。” | 正确有据 | no | accurate | yes，前提是归属确实正确 |
| “目标是x，但目标的记录互相矛盾。” | 正确有据 | yes | none | no，即使选值正确 |
| “目标是x，但记录有冲突。” | 正确有据 | unknown | unknown | unknown，不能仅凭关键词定归属 |
| “无法确定目标。” | no_answer | no | none | no；目标明明有据 |
| “答案是y……更正：目标是x。” | 正确有据 | no | none | yes，前提是y明确完整撤回且无其他问题 |

若回答说“目标是x；不同来源对另一对象有两种说法”，应核对文本中两种说法、对象及字段，而不因它多解释而扣分。若评审认为它实际暗示目标也有冲突或未撤回矛盾，须据具体文字重新评字段，不能照搬表格。目标已真实冲突的CT应独立记录是否识别目标冲突、是否在未获消解条件下选边；不能把SO的T=yes错误规则套给CT。

拟议分析应保留完整计划分母、每条件技术失败/未审/参考unknown/行为unknown、已审组合及底题配对；可报告yes/no/unknown识别范围，但不把识别界当置信区间。主次终点、容差、样本与统计方法在条件成立后另行固定；本口径不是已采纳的数值门槛或放行决定。

## 4. 本轮定向近邻及等价性

| 研究及原文 | 实际比较与对象 | 本候选差异和限制 |
| --- | --- | --- |
| [Wang等，Resolving Knowledge Conflicts，COLM 2024，arXiv:2310.00935v3 §2.3 Task 2](https://arxiv.org/html/2310.00935v3) | 在含与模型参数知识冲突内容的上下文中，分别生成关于冲突段及非冲突段的问题，问上下文是否与模型既有知识在问题答案上冲突，评二分类。 | **目标范围冲突识别已有非常直接的先例。**它是单上下文与参数知识冲突/显式二分类，不能直接等同双外部来源、目标可答及生成回答的额外错误归属；但两者相似足以大幅收紧创新。版本与任务按该v3原文，未核查全部公开数据样本及后续引用。 |
| [EviScope v1 §3–5](https://arxiv.org/html/2609.17081v1) | 同题支持、噪声、缺证、目标冲突四条件，生成回答与引用；两名评审覆盖论文所述160输入。 | 有行为、来源及配对，但所查表格未单列目标唯一且**非目标内部真实冲突**；没有核全部材料，不能说肯定不存在。 |
| [QACC，NAACL Findings 2025](https://aclanthology.org/2025.findings-naacl.99/) | 人工标注开放域检索上下文中的相互冲突及解释，考察问答。 | 真实来源/多解释很近；本轮按摘要及论文引言核实，未认证其有无目标唯一+非目标冲突的配对或适合权利。 |
| [RINSE v1 §3–4](https://arxiv.org/html/2609.37469v1) | 固定证据更换问题、证据充分/不足配对、单侧线索审计，生成前评分。 | 问题范围和控制策略已有；二分类证据不足与两个外部来源的非目标冲突并不等价。 |
| [Logic Haystacks，EACL 2026](https://aclanthology.org/2026.eacl-short.3.pdf) | 形式化目标矛盾所需证据与不干扰背景。 | 形式保证及目标相关性已有；不自动解决冲突来源按谁的说法评分及自然语言判断。 |

这些定向查证不等于系统综述或对全部代码/样本的审计，也不能保证没有等价研究。当前仅能说：**双外部来源中非目标冲突如何影响可答目标的回答，是比宽泛范围冲突更具体的候选；是否足以构成实质增量仍未证明。**

本轮无新实验材料、评分、评审调用、模型前向、GPU、拟合、patching或380正文访问；原v1/E1-r1门禁false、正式独立批准0、正式标签null、原拟合预算0，380正文封存。必要GPU由用户执行。
