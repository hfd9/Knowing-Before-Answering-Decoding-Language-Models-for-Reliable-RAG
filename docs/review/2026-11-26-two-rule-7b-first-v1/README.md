# 两条新规则的 7B 首轮开发采集

状态：`prepared_not_started`。本包固定[选择前协议](../2026-11-26-new-rule-development-protocol-v1/protocol.md)及[作者材料和来源](../2026-11-26-new-rule-materials-v1/README.md)，并不改变原确认门禁或把材料变成独立法律参照。两条规则在协议固定后选取，但一旦查看输出即为开发材料，不再作后续未见规则留出。

## 输入及检查

SEC 管理资产门槛和 IRS 投资收入限制各两种金额；每种金额包含缺日期、旧日期、新日期，共 12 题；同一 7B 的直接与逐版路线各 12 条，合计 **24 条独立首轮**。两个路线公共问题、事实、证据摘录和作者版本元数据完全相同，仅路线指令不同。模型输入不包含内部 same／different 案例标识、逐题作者参照或配对另一题。

原文摘录和作者编写的版本元数据分别标识；这是受控材料而非实际检索或自然用户问题。IRS 两个纳税年度起始日相隔一年，旧冻结 3B 管线不能无损直接接入本材料；本包只执行两条 7B 路线，不将历史结果充作同模型第三路线。法条范围、例外和参照均为知情作者核对，尚无独立法律复核；来源的具体再分发用途也仍待核。

[计划](plan.json)和[清单](manifest.json)绑定协议、材料、参照、实现、模型文件及依赖的哈希和 token 长度。真实 tokenizer 输入 388–432 token，模型上下文 32768；每条最多 768 新 token，bf16、贪心、单条串行，两个路线预算上限相同。上限并不保证无截断。25 项相关 CPU 测试通过，包括完整／截断合成运行、封存篡改拒绝、已有运行目录拒绝覆盖和路线公共输入一致；模拟模型不证明真实 GPU 能正常推理。

首轮完成并核验后，先封存对缺日期题是否明确追问事件日期的逐条判断；仅实际发生明确追问时才准备两日期独立续轮。此包不自动生成续轮，不能把仅“取决于日期”或主动补充说成真实追问。

## 用户运行

按用户 GPU 执行约定，先用 `nvidia-smi` 检查所选设备是否空闲。以下一整行使用物理 GPU 0；若改用其他设备，只修改 `CUDA_VISIBLE_DEVICES`。

```sh
CUDA_VISIBLE_DEVICES=0 ANSWER_CHANGE_USER_EXECUTED=1 /large_disk/wf/miniconda3/envs/kba-rag/bin/python scripts/answer_change_two_rule_dev.py collect
```

请在项目根目录运行，预留约 10–30 分钟；这只是估计，真实磁盘重哈希、模型加载、24 次生成及输出长度尚未测量。程序检查一个可见 CUDA 设备、bf16 和 18 GiB 空闲显存，但不能保证独占。空输出、截断或异常会停止并保留现场；若报错或结束，请把终端输出交给助手，不要删除 `runs/answer-change-two-rule-7b-first-v1` 或重复运行已有目录。助手将先核验 token、EOS、材料和 seal，再按协议知情评分；真正续轮另行准备。

本包不启动正式论文主实验，不改变旧十题暂停、380 题正文封存、原门禁及预算。
