2026-11-09，Asia/Shanghai。用户要求完成数据来源、语义参照、资源与研究价值三步。本次查原论文、作者数据卡/仓库及本项目既有记录，检查公开网页显示的字段和示例；**未下载全量数据、未构造或选取研究样本、未连接全量qid、未评审新输入、未运行模型/probe**。网页可变化，未锁定远端数据提交；仅凭网页不能证明文件完整、许可证适用、底题不重叠或任务语义成立。

## 2. 语义参照能否成立

FaithEval论文说其不足和冲突材料经过LLM检查及三名人工评审、多数决定；这为原始记录提供比本项目知情作者参照更独立的外部证据，但不是对每个未来任务改写的认证，也未取得逐评审原始投票或证明零错误。[原论文§3.2](https://arxiv.org/html/2410.03727v3)中这一程序的对象是原context任务及筛选条件。候选可行性逐项如下：

| 需要判断 | 目前实际可用证据 | 仍需的核查与失败处理 |
| --- | --- | --- |
| 原I是否缺证 | FaithEval原始缺证标签、上下文与理由，有论文披露的人工验证 | 按问题及完整最终文档检查能否唯一推出目标值；不能以答案字符串缺失等同不可推断。若新干扰文档泄漏答案或歧义无法解决，记unknown/排除原因。 |
| 原C是否目标冲突 | 同题两答案/冲突上下文、构造理由和人工验证 | 检查两处证据针对同一实体、时间、范围及字段，且两答案互斥且无消解依据；文档外真伪本身不裁定内部冲突。单独审核将拼接上下文拆成文档的改造。 |
| S是否唯一支持 | 冲突材料所含原/新上下文理论上可提供候选，论文曾分别评估 | 页面预览及原审稿不能证明分离后的每端均唯一支持；取单侧会改变证据集，须单独核对完整最终S。 |
| 两表达是否保持状态 | 原始版本与论文来源并不提供本项目拟议的已审核A/B对 | 若后来另行设计改写，按逐命题及实体/范围/条件逐对评估；记录编辑位置、token长度、潜在答案/冲突泄漏。不能把文档顺序交换或复制文本自动称为语义全等价。 |
| 五文档及干扰 | FaithEval上下文结构并非已经验证与本项目固定五文档输入一致 | 将来如需要拆分/补干扰，每个最终完整输入必须复审；不得将原标签原样转给重新包装的输入。暂无已完成五文档映射。 |

建议未来有条件地采用**两阶段独立输入审核**：先固定材料、逐槽文档和来源/派生记录，再由彼此分开的评审会话仅根据问题和完整输入分别记录S/I/C/unknown、支持或冲突证据及理由、表达是否保持关系；先封存原结果再连接题组和probe结果。保留可观察的输入、会话和模型来源，不能只因随机ID或不同会话就声称历史隔离；未能核实上下文时如实降级为可追溯但非正式独立。分歧保留双方及引文，未解决的完整底题不得悄悄变成正确/错误；报告原计划分母、unknown、排除与覆盖率，并对不同可行裁决给出敏感性界。现有人工验证可能降低新审核工作量，却不能替代对新包装及改写的审核。使用LLM辅助是可能路线，但本轮未实际验证是否有两个上下文可认证的评审或其错误独立性；用户无需本人逐条审阅。若未来独立性不足，报告为探索而不是通过旧正式门禁。

## 3. 数量、成本与研究价值

以下是**数量级示意，非方案、运行预算或新的门槛**。假设每底题有三状态×两表达=6个完整输入，主指标是每个状态两表达都符合参照的底题比例，三状态同时给出单侧95%下界；进一步假定底题独立同分布并使用Bonferroni，每个状态在**零失败**时单侧精确下界为 `(0.05/3)^(1/n)`：

| 仅用于解释精度的假设下限 | 零失败所需n底题 | 对应输入 | 备注 |
| --- | ---: | ---: | --- |
| 三状态各大于0.90 | 39 | 234 | 下界约0.90034；38题时约0.89786。 |
| 三状态各大于0.95 | 80 | 480 | 下界约0.95011；79题时约0.94949。 |

这不是实际推荐合格率、功效分析或样本量决定；一旦有失败，所需底题数更大，抽样偏差、分布变化和语义标签错误不由该区间解决。样本量最终必须由具体用途、可接受误差、预期失败、有效覆盖和统计方法共同决定。不同状态同题相关，Bonferroni不需要状态间独立；公式仍要求每一状态内底题层面的二项模型条件。若只是举例假设80%底题最终有完整可判参照，得到39个有效底题的期望起始规模约49个，**不保证**实际获得39个；每候选6输入、每输入两次审核将约为588次输入审核（可按底题打包，但每槽与表达关系仍须核验），重审和分歧另计。具体审查耗时和服务费用取决于材料、会话和实际平台，当前无实测，不能给出可信货币预算。

仅作为设备数量级参考：[旧绑定48](../../records/2026-10-21-behavior-binding-probe-results.md)记录48次前向耗时合计5.30秒，[等token13条](../../records/2026-11-09-probe-neutral-control-results.md)记录7.075秒；两者均不含完整模型加载和运行前后校验，前者输入很短，后者只有13条、无终端运行日志；不能线性推算新长文档集的实际耗时。未来需先固定token长度分布和实施方式、做CPU准备，再由用户执行经批准的设备检查/小规模技术预检，才能估时；本次无GPU预检或命令。冻结probe无需新拟合；任何文本分类、阈值或训练型比较若需拟合，须单列经审批的训练/验证底题、预算和版本，不能从原拟合预算0中自动支出。无拟合基线如固定始终预测单类可作下限，但不能解释捷径；文档长度、标记和重复等无需训练的描述统计只能诊断输入差异，不能证明因果。

**收益对照。** KBA已经研究原发布三状态和提示扰动，其RAGTruth自然迁移是二分类；[Hidden Commitment附录C](https://arxiv.org/html/2610.38296v2)已对FaithEval冲突数据用同题顺序交换、一致改写与单文档对照；ContextConflict已有冲突/一致配对及probe。潜在增量仍是同一冻结三状态读出上同时测审核后的S/I/C与关系保持表达变化，尤其缺证状态；但候选FaithEval缺已验证的五文档/改写、原材料部分人工验证不能直接转移，现有结果也不能证明这个组合作为论文贡献足够新颖。

## 本轮去留和可执行的下一步

**结论：条件性保留FaithEval作为下一阶段元数据可行性候选，暂不进入确认实验或起草运行协议。** 可观察的同qid与人工审核证据改善了可行性判断，但不足以通过：①全量qid交集、重复率和实际可用的同题S/I/C数量未知；②改造后语义参照、评审上下文隔离和五文档一致性未知；③原数据及各上游的使用/保存/再分发条款未核完；④排重不读取380题时的剩余碰撞风险未量化；⑤预定用途和容差、真实审核成本及差异价值未确定。

下一步若继续，先只做**不运行模型的来源清单与交集可行性检查设计**：为两个FaithEval版本锁定发布修订与数据使用边界，明确只输出匿名qid计数/去重与子来源分布，不阅读或建立新实验样本、不碰380题；说明如何与已授权的训练/验证/探索来源核对，保留无法覆盖的风险。是否实际获取全量元数据及执行连接须遵守“不自动扩样”和版本治理，不把统计探查包装成已批准数据采集。只有交集与条款均通过、参照审核途径及研究价值也清楚时，才考虑另立候选协议；任一项无法达到则停止并保留既有结果。旧v1/E1-r1门禁false、独立批准0、正式标签null、原拟合预算0、380封存；不重训、不搜索阈值、不patching，未来必要GPU由用户执行。
