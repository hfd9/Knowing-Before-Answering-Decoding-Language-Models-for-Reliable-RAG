# 两条新规则开发试运行协议 v1

状态：材料选择前的开发协议；本协议不是论文主实验、独立留出或对法规的法律意见。固定本文件后才选择新规则；规则、题面、参照、实现、模型及用户运行计划尚须分别固定和核验，真实采集尚未放行。若后续修改本协议，保存新版本并说明当时材料及输出的暴露，不能把已见结果作为新版本的独立检验。

## 目标与对照

用两条此前未用于本项目分析的规则，测试同一 7B 的两种提示在完整版本证据下能否分辨缺日期的同答与异答，检查条件回答、引用及补日期后行为。每条规则为一个独立规则单位；两条仅用于开发，查看输出后转入开发集，不可用于后续 8–12 条未见规则。

主要对照固定为本地 Qwen2.5-7B-Instruct 的直接回答与逐版比较；模型文件与依赖的历史哈希见[7B 清单](../2026-11-25-answer-change-7b-development-v1/manifest.json)，运行时必须重新核验。相同原文、版本元数据、问题、事实、日期范围、回合数与输出上限，单次独立会话、贪心、不采样、单 beam；两条路线仅改变下列路线提示。拟定最多 768 个新 token，须先以真实 tokenizer 检查输入加输出不超上下文；任一空、截断、异常立即保留现场并停止，不静默重试。更换模型、版本、上限、提示或评分须生成新协议版本，不能在看过新规则输出后继续称同一冻结协议。

旧冻结 3B 抽取器如能在保持其原始算法和受控输入的前提下接入，只作为附加的**系统级**对照，保留人工结构、型号、设备、选择前向与输出差异；不得当作同模型方法消融。若形状不支持、模型或运行资源不可用，明确记未运行／不适用，不补写答案。首要的 7B 两路线可先独立完成；没有 3B 同题运行时，不能编造其成本或效果。

## 规则选择及材料准入

固定协议后，按公开来源检索顺序记录候选、逐一判断而非根据模型表现挑选；不得访问 380 封存正文。每条拟选规则应满足：

1. 对应单一清晰的金额门槛、比较方向和事件日期，两版门槛不同；两版规则在题面限定范围的两个日期分别有效，且完整覆盖这两个日期。优先同一权威来源的原文和修订／年度变更文件；如规则与数值分别出现，明确记录各自来源、原始发布日期、适用日期及推导。不得把公告发布日直接当法定适用日。
2. 能固定其他案情和适用范围，只改变一个金额，构造两个问题：两日期同答、两日期异答。需显式核对相等、稍低、稍高的边界及例外；两天不代表法规只在两天有效。若无法对某一范围或例外建立可靠参照，标 unknown 并排除该候选，保留原因，不能将作者假设伪装成原文。
3. 问题、简短事实、规则原文摘录和必要版本元数据应对两条路线完全一致。法条原句、权威来源数值、作者编写的时间范围／案情必须分别标识；事实、可能日期及当事人条件可以由作者构造，但不能将它们标成真实案件。每段给稳定 ID；版本元数据的来源和有效期理由单列；不向模型泄露正确结论、同答／异答标签、逐题参照或配对另一题。
4. 记录来源链接、固定版本与读取日期、允许的本地研究、摘录与提交范围；不因为代码许可或政府来源就自动推断所有发行用途已闭合。两条法规应尽量属于不同规则而非同一年度表的重复改写。来源条件不能落实就排除，两个合格候选未凑齐则说明实际数量和阻碍。
5. 对照规则、版本、事件、案情金额及逐日答案的参照由作者先行建立，保存出处及字面引用，并由独立具备判断能力的人复核；若无人可复核，可仅在明确标为作者知情、非独立法律复核的开发条件下继续接口试运行，不把参照说成独立 gold 或据此启动正式确认。无法消除歧义的题不纳入有效参照分母。

对每条规则以两种金额各生成三种题态：缺事件日期、明确旧日、明确新日，共 6 题；两条为 12 题。每题直接与逐版两路线共 24 次首轮生成。主要配对是同一规则的两道缺日期题；4 个已知日期是分支对照。有限两个日期须在题目中明确；它们是作者限定的任务范围，不向模型揭露同答／异答。

## 固定首轮提示

消息采用模型原生 chat 模板；证据块、案例事实、日期范围和问题按材料固定原样插入。日期未知题允许澄清或完整条件式回答；已知日期题要求仅就该日期回答。资料原文和作者元数据作明确区分，引用使用稳定 ID。

系统消息：

```text
Use only the supplied excerpts, version metadata, and case facts. Cite evidence IDs. Do not invent evidence or facts. If evidence is insufficient, say so.
```

公共用户消息：

```text
Question: {question}

[F1] Case facts: {facts_and_date_status}

The possible event dates for this task are {old_date} and {new_date} only.

Evidence and version metadata:
{source_excerpts_and_explicitly_attributed_metadata}

If the event date is not given and no unconditional unique answer is justified, you may ask for the event date or give complete date-conditional conclusions. If it is given, answer for that date.
```

不额外以“作者判定范围来源是 E 编号”的形式告诉模型角色；若来源原文本身可直接辨认，不修改文本来隐藏。两路线均能看到完全相同的元数据。

直接路线附加：

```text
Answer the user question using the supplied evidence and possible dates. Explain and cite the evidence for your answer. If there is no unconditional unique conclusion, respond usefully as allowed by the question.
```

逐版路线附加：

```text
First state the applicable dates, conclusion for the case, and supporting evidence IDs separately for each relevant version in the possible date range. Then compare those conclusions and answer the user question. If a version or scope is missing or unclear, say so rather than guessing.
```

对已知日期题，逐版路线保留同一指令；只评价题目实际给定日期的最终结论，额外讨论其他日期不能掩盖对实际日期的错误或矛盾。实际 token、模型加载、运行时间和调用次数须记录；生成上限是相同上限，不声称消耗相同。

## 首轮次序、补日期与失败

每规则按同答缺日期、同答旧日、同答新日、异答缺日期、异答旧日、异答新日；每题直接先于逐版，共 24 条。此顺序非随机，需披露；每条独立上下文，不能包含另一题或另一条路线的输出。

首轮全部封存并技术核验后，对缺日期题逐条判断是否**明确请求该事件日期**：直接问句或明确要求用户提供该日期均算；仅写“取决于日期”、给分支、泛称信息不足、引用无关日期均不算。无法判定记 unknown，不默认为追问。先固定并封存判断和完整原始输出，再仅对已判定为明确追问的会话分别补旧日及新日；两个续轮均从原首轮历史独立分叉，不能串联。格式为：

```text
The {event} date is {date}. Please answer the original question for that date and cite evidence IDs.
```

如首轮未追问而需要检测主动补充，只能单列为另一个压力测试，不能放入追问后正确率。首轮缺日期共 4 题 × 2 路线 = 8 条，最多少于或等于 8 条有效追问、最多 16 条续轮；实际分母为明确追问后收到预设日期回复的有效分支，同时报告覆盖率。若无明确追问，续轮指标未定义。真实追问文本的事件是否可区分两日期、是否已经给过日期分别计分；不强制模型为了产生续轮而追问。

每条记录保存完整消息、输入 token、生成 token、原始输出、EOS／截断、状态、调用时间、模型和运行环境。先写 attempt、后写 record；任何失败保留现场并停下；不覆盖、不补跑原 attempt。技术问题引起的任何新尝试均另记新版本、暴露和历史，不把处理后的结果重新冒称未暴露。收集前准备代码、CPU 测试、模型及来源哈希、时间估算与 GPU 用户执行说明；用户运行 GPU，助手核验后再评分。

## 评分与分母

先封存原文；用[开发评分手册](../2026-11-25-answer-change-7b-followup-v1/scoring.md)的严格结论、宽松等值推断、内部矛盾、逐命题引用和 unknown 规则，适配本协议的首轮和真实追问后续轮。特别区分：只有一个正确答案但没有明说或可靠推出跨版本一致时，“唯一性判断”可为 unknown，即使回答内容恰好正确。明确的完整逐版判断可支持同答／异答识别；不能将“可能需要日期”自动判为知道异答。

- 每路线每条规则的**唯一性判断成对正确**：同答、异答缺日期题都明确或由完整正确分支可靠支持应有的可判定性判断。两条规则共 2 对，unknown／矛盾／生成失败不算正确并单列。
- **回复有效性成对正确**：同答题给正确且引用充分的结论；异答题给有据、完整且正确的条件结论，或明确追问可区分版本的事件日期。逐条标注内容、引文与是否仍需交互，不能把条件式正确视为错误唯一。已知日期题另报最终正确及引用。
- 分别报告无条件错误唯一答案数／全部 2 条异答缺日期题、无谓追问数／全部 2 条同答缺日期题、逐日正确和引用状态、生成失败／截断、调用次数及成本；所有分子、计划分母、有效参照数与 unknown 均公开。
- 引用精确 ID 与语义是否充分并列。题面事实可在语义层作为事实来源，但显式 F1 和旧严格 ID 集合另列；不要求唯一 ID 集合排除其他等效引文。语义评审须注明哪些命题由何处支持，不以所有相关材料恰好存在来自动判引用充分。
- 明确追问后第二轮对旧／新日期分别报告内容正确和有据正确，并报可判定评审比例；主分母列实际预设的全部已运行追问分支，失败和 unknown 保留。模型未实际问的分支不纳入此指标。

两规则、作者构造案例和知情评审只用于诊断界面及评分，所有比率列出分子分母，不能声称总体发生率、独立法律准确性或方法优越性。生成及评分后，逐题汇报完整原文和实际错误，复核语义分歧，再修改协议并记录暴露；后续留出须在修订冻结后选择全新规则。
