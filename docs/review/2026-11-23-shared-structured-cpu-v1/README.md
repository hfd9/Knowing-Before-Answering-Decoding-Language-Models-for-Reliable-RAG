# 两题结构化 CPU 工程验证

基于[简化格式复跑的故障](../2026-11-23-shared-lines-results-v1/README.md)，建立单独的两题工程接口。保留上轮的解码、原文和评分记录用于回归。此次与上轮的可读性对比反映接口约束变化。模型和设备精度、提示及输出策略也有差异，两轮的判断准确率仅作描述。

- 抽取兼容裸 JSON 数组及一层完整的 Markdown JSON 代码块。保留原始响应，并记录使用哪种格式。值的类型、重复值及标识符仍按原规则检查。只有实际抽取的两个值与原文两来源精确对应时，才启动联合和分支。错值或无效响应保留为未解决。
- 直接组用两个原文来源槽表示世界。程序从各来源的原始字节跨度定位值。联合和分支的世界按同一次实际抽取映射，顺序保留。固定两来源的直接组省去了重新生成候选值，改变了直接组的任务定义。
- 对判断输出用本地 tokenizer 枚举有限合法前缀，限制输出只能包含对应世界行。模型可选择 Y、N 或 X，证据可选择空集或公有证据编号的任意子集。可选错证据。程序合并逐世界标签，任何 X 产生未解决。最终标签合并是程序行为，不作为模型独立汇总能力。
- 数值程序对照用实际抽取匹配原来源，再从原问题识别“超过”与“低于”、阈值和单位。三条问法均在限定模板内，单位不匹配或抽取无效则未解决。程序输出独立计分，模型仍保留自身判断。

## 真实模型结果

本轮在 CPU 上以 FP32、16 线程运行本地 Qwen2.5-3B-Instruct。计划 26 槽全部实际生成，26 条均以 EOS 结束，无跳过。两次抽取实际仍输出带围栏的 JSON，候选为 34/58、VX3/LM7。新版解析器均接受，18 个下游调用全部执行。24 条模型判断输出均可按约定读取，世界对应原文值。
