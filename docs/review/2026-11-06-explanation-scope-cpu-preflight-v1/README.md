## 有限模型检查与保留的语义边界

[检查结果](finite-model-audit.json)与[只读检查程序](../../../scripts/audit_explanation_scope_models.py)直接从48条实际问题及文档提取三个记录赋值，在每题的两个实体×两个字段上，以该场景的三个显示值和一个未显示值为有限域，穷举4⁴=256个赋值世界。这里的“世界”是离线计算，不是新材料、模型回答或自然语言语义认证。

| 条件 | 将全部记录均作为真实约束时 | 一个冲突记录的局部修复 |
| --- | --- | --- |
| S | 每题4个世界，目标字段仅有被记录的一个值。 | 无冲突，无需修复。 |
| I0 | 每题4个世界，目标字段可为有限域的4个值。 | 无冲突，无需修复。 |
| IU | 无世界能同时满足所有记录。 | 删除任一条冲突记录后各16个世界；每种修复下目标字段均可取4个值。 |
| CT | 无世界能同时满足所有记录。 | 删除任一条冲突记录后各16个世界；每种修复下目标字段固定为另一条记录的值。 |

这是条件化的数学检查：保留的记录被当成约束，有限域也不是所有可能世界。**若采用“所有记录都可能出错”的另一种解释，S也不能由单条记录确定世界真值**；仅能说该值获得一条记录支持。材料使用“根据所给记录”回答，因此可以保留记录相对支持这一操作口径，但不能把它升级为真实值认证。IU/CT的局部修复只展示可能性，不假设冲突两条记录恰有一真，也不穷举两条均错误的情况。若将来审核认为该记录语义不足以支撑预定问题，应在采集前保留歧义或另存修订，而不是自动判通过。

## 48条候选顺序及技术预案

[执行预案](execution-draft.json)绑定v2设计、材料、匿名包、协调见证、作者侧解释、既有token检查、原研究草案和评分契约的SHA。先固定exs01的S/I0/IU/CT四条为技术smoke，计入48；其余44条按固定字符串和ID的SHA排序，顺序在任何回答生成之前保存。计划中的greedy128、一次attempt和失败停止都是未来实现的约束；本文件没有生成入口，不授权采集或GPU。

预案要求先写带协议绑定的attempt，再保存结果；未提交attempt、孤立记录、顺序错误或失败标记都应停止并保留证据，不自动重答。前四条须检查非空、EOS、未触顶和输入/顺序绑定，smoke失败不进入第五条；技术smoke不使用解释是否正确作为通过条件。真实实现还需独立实现和测试锁、文件原子写入/同步、缓存解码与输出哈希、进程中断恢复、GPU空闲检查及实际模型权重指纹。这里没有实际attempt文件、预测文件、运行目录、模型输出或恢复操作。
