# 固定候选世界的规则适用性 CPU 检查

2026-11-23，Asia/Shanghai。为判断模型是否有机会在「哪条规则适用」这一步带来收益，制作并复核了三种受控条件的成对案例，并为其中的授权方向另加一对改写。它们共八个版本、四对，授权改写与原例共用同一机制。全部案例由知情作者构造及核准。

[公开案例](cases.json)固定 A/B 两个候选世界与同一个查询。A 始终准入，B 默认不准入。B 的豁免是否适用由每对的唯一事实差异决定。豁免适用时，结果为 Y/Y → Y。明确不适用时为 Y/N → U。读不到决定因素时记为未解决，保留不同于 U 的状态。[作者参照及逐项依据](author-reference.json)

| 对照 | 改变的事实 | 初始确定性解析 | 扩展解析 |
| --- | --- | --- | --- |
| 对象范围 | 两个登记名指同物或异物 | Y / U | Y / U |
| 日期边界 | 含当天的起始日或前一天 | Y / U | Y / U |
| 授权方向 | 只交换授权方和受权方 | Y / U | Y / U |
| 授权方向改写 | 只交换「替谁签发」与「谁可以代签」 | 未解决 / 未解决 | Y / U |

两组授权方向对照在各组内拥有同样的字符计数。只看字符是否重合或出现多少次，无法区分句子的方向。加入有方向的角色解析，原授权句可区分。初始句式覆盖 **6/8**，对未覆盖的改写保守返回未解决。增加一个针对代签句式的规则后，扩展解析达到 **8/8**。扩展规则是在看到这对改写后加入的。给程序输入作者规范化事实时，下游逻辑也为 8/8。这项对照把文本解析和规则推演分开。

三条比较路径均使用设计时给出的结构化规则条件、固定候选世界和同一规则优先顺序。本轮的解析对象是事实句，规则文本到规范化条件的自动转换不在测量范围。没有独立语义审核或新的未知分布检验。后续若以模型为候选，必须用规则句和事实句都需要解释的材料，在开发集写规则，在预先保留的改写或新模板上与确定性解析比较。仅在看过两条改写后写到 8/8，无法估计泛化，也不足以证明模型的使用收益。

当前决定是暂不启动模型对照。这轮找到了无序词面匹配的明确反例，但匹配失败的受控句式已有有限程序解法，尚未找到需要为单独模型实跑投入资源的已核准材料。继续保留授权方向案例作为检查适用性的最小诊断。原十题暂停。

[CPU 检查脚本](check.py)先算确定性两种路线，再连接作者参照。[逐版本结果](results.json)保留 Y/N/X、证据 ID 和两份输入摘要。四项边界测试覆盖日期、实体不匹配、授权方向、授权冲突、未知和改写。未调用模型或 GPU，未读取封存材料。
