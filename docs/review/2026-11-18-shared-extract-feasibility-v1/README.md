## 4. 待审方案：有清晰输入边界，尚非运行协议

以下是供实现和评审的候选，不假装世界、题目、提示、答案及容差已冻结：

1. 同一底题三问题：两个世界同为Y、同为N、各不相同。只允许由可审计来源和清楚的两世界穷尽假设构造；作者先封存结构、来源、逐世界答案及依据。题目本身不得泄露世界标签或参考答案。
2. 直接组看冲突证据和问题，显式要求逐候选比较；抽取组先对同一背景实际抽取一次。联合组接收相同证据和这次预测的两个候选，明确它们是候选；分支组各自接收相同来源材料和一个临时假设，不把假设叙述成已证实事实。联合和分支严格共享实际抽取，不能用参考修正。待审解决点：冲突原文与单世界假设如何共存、模型如何引用足以核验每世界推理的短证据、不同提示额外信息如何影响公平性。
3. 固定输出结构、解析器、原始token与提示哈希、空/截断/失败政策，问题及两分支来源分别留证；技术失败和语义无效不得补做或抛出分母。需要具体审查并测试smoke、未提交attempt与可恢复性。候选同答“正确且有据”须答案正确、两个世界的依据可逐字核验且支持对应判断；分歧题需正确表达不确定。引用存在不能自动证明推理成立，暂不能把程序字符串匹配视为独立语义认证。
4. 分母按完整计划的底题、同答/异答及方法列示，先保留未解决与失败，再报告每对方法的逐题转换；按底题聚类，不把共享世界的三问视为独立。至少报告强直接、联合、分支各自实际调用、输入/输出token和端到端时间；抽取分摊和真实执行墙钟分开。
5. 可供讨论的保守开发筛选：只在联合组在每个同答题都不比对应分支组差、异答题无新增无依据选边且未解决不增的情况下，因成本考虑优先联合；其余情况继续分析或暂停。此逐题支配只是**候选启发式，不是功效分析、确认验收或已采纳的用途容差**；即便满足也不保证未来总体安全。
