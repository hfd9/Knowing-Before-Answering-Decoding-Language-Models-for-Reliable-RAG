# 多规则 v2：选择新规则之前的草案核查

状态：已暴露开发结果后的设计审阅；v2 仍是草案，不是采集放行。下列事项将“已有文字”“下一步要固定的内容”和“当前资源状态”分开；不从两条旧规则作参数调优，也不选择新规则。

| 检查项 | 草案已有内容 | 冻结前仍要落实 |
| --- | --- | --- |
| 研究问题 | 同一 7B、同一规则及金额，比较缺日期与两个明确日期的回答；同答和异答配对。 | 固定三态逐条评价表：分别记实际日期结论、整答矛盾、版本引用、缺日期行为；“两个已知日期都正确后再看缺日期”是筛选后的描述性分析，须同时报全集，不能当独立随机样本。 |
| 摘录范围 | 要求保留原文主体、比较符、法定事项和必要限定，作者元数据与原文分开。 | 固定来源版本、摘录边界、字面引用和适用日期的可复核证据；若时间元数据并非摘录本身，记录其上游依据与已授权用途。不能以页面可访问代替具体用途许可或法律复核。 |
| 虚构日期 | 区分把未提供日期当作事实、无条件唯一结论和基于虚构日期只答一分支。 | 固定标注细则及边界样例：同答时最终数值恰好正确但日期假设错误，应分别标内容正确和事实假设错误，不能只选对模型有利的标签；条件式“如果”不得误记为声称事实。 |
| 条件式回答与追问 | 完整正确的条件回答可有效；真实追问须明确请求所需事件日期。 | 固定引用充分性的分支要求、同时给条件和追问的计法、明确日期后重复追问的计法；主观语义分歧保留 unknown，不凭单个程序关键词裁定。 |
| 未知和失败 | 保留 unknown、矛盾、无效、截断、未执行，报告计划和已运行分母。 | 把每种状态放入评分表与汇总程序，明确首轮中止时其余条目为未执行，不算模型答错；样本不能因结果不佳而事后剔除。 |
| 两阶段复核 | 要求有能力且未看过输出的人核对输入和分支，再审回答。 | 已准备[六条 IRS 实际输入包](../2026-11-26-irs-input-review-packet-v1/README.md)，但仅覆盖一条规则的两个直接路线三态组；没有真实评审提交，不能外推为全部八组或所有规则已独立复核。任何评审者身份、能力与历史暴露需实际确认并记录。 |
| 调用量及路线 | 8–12 规则，各 6 题、2 首轮路线；每个实际追问最多 2 个续轮。 | 算术上首轮 96–144，续轮最多 64–96，合计上限 160–240；不等于已经批准预算或预计一定发生。明确实际规则数、运行时长、GPU、费用上限及失败处置后再实现和固定。 |
| 可复现实现 | 继承 v1 的同一 7B、两提示和独立会话作为候选。 | v1 写的是两规则固定顺序和 24 首轮；不能直接把它的具体数量或旧 24 条运行器当作 v2 的 8–12 规则实现。须确定 v2 顺序／随机化、固定种子、提示模板及代码与文件哈希，在选择新规则前冻结；不因看到输出再改动。 |
| 去留判据 | 比较完整材料的阅读、必要时再测检索；无独立法规复核时不称确认集。 | 先记录两候选组是否经适任者输入优先复核，决定是否有足够理由使用 8–12 条；不能凭作者事后挑出的同一 IRS 规则两个金额自动推断跨规则效果。若扩展，只称事先定义的跨规则可行性检验。 |

当前两候选组的已知事实和可能分歧见[三态审计](../2026-11-26-first-failure-triads-v1/README.md)：按旧标签“两个日期实际结论正确”有 4/8 组，其中 3 组缺日期未通过；再排除明显整答及版本引用问题留下两组，两组共用 IRS 一条规则。是否能给独立审核者，以及其判断是否一致，尚未知。

建议顺序：先检查是否有真实输入复核提交；没有则继续完善机器可复核的标注和数据来源合同，而不是创建假评审或启动 96–144 次采集。可在不改变旧结果的前提下制作合成边界样例；等复核资源、来源用途和运行资源可核实后，决定是否冻结 v2，再选择新规则。检索方向保持后置。以上是后验设计审查，不是已冻结规则或新的性能结论。
