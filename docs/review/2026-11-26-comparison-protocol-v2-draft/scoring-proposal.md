# 评分聚合候选方案：供冻结前审查

状态：**候选方案，不是冻结协议，不重算既有结果**。该方案在已见两条开发规则的输出后提出；合成代码只聚合人工输入的标签，不从文字推理语义，不判断法律正确与证据充分。

## 建议的回复与交互指标

逐条先标注来源充分性、完整条件结论、事实假设、日期请求、整答一致性和引文支持；每一项记证据位置、标注理由、评审角色和暴露，分歧保留 unknown。再分别计算：

1. **结论内容**：在所给日期窗口内是否给出正确结论，或是否正确写全覆盖该窗口的条件分支；该指标不自动认定事实假设或引文正确。
2. **首轮回复有效性（候选严格口径）**：同答时要求结论正确、无把缺失日期当成事实及无实质矛盾；异答时接受完整正确条件答，或者明确询问能区分版本的事件日期；任何选项均不能包含与之冲突的错误断言。引用充分性另报。即同答题结论碰巧正确但虚构事件日期，内容可正确，严格回复有效性为否。实质性与充分性无法判断时保留 unknown。
3. **用户交互**：分别记明确日期追问是否出现、是否为作出完整正确条件答所必需、是否已得到最终答案。完整条件答后再问日期，记“完整答案 + 存在追问”，不把它改写为“只追问”；候选必要交互数为 0，实际有无发生后续用户回复另记，不由首轮推断。若仍需用户给唯一的实际事件结论，则追问可满足该需求，应单列“获得唯一结果需要用户答复”，不得把条件结果当作唯一结果。对任务意图不清或追问是否有必要有分歧，记 unknown。
4. **证据**：逐命题记录引用 ID 的出现、旧严格 ID 匹配和人工语义支持，不能互相替代。语义未复核不补为正确；独立盲评是否可用单列。

同答要求直接给有根据的结论，异答允许正确条件答或有效追问。每条规则成对成功需同答与异答在同一路线上都满足选定口径；`yes AND unknown = unknown`，但 `no AND unknown = no`，因为已知一端失败足以确定该对不成功。规则材料参照不充分或未能确定时，须先标参照可判定性；不得只挑可评分案例而不报排除原因。

## 分母与 unknown 的建议展示

每指标都报告计划量、各运行状态数量、已完成量、可判定的 yes/no、unknown，以及相应参照可判定数量和排除原因。以下范围仅表示**已完成输出中，把未知标签分别按全部 no 与全部 yes 假设得到的算术范围**，不是置信区间、不是总体性能区间，也没有为截断或未运行假造结果：

> 完成数 N > 0：下限 = yes / N；上限 = (yes + unknown) / N。

N = 0 时两端均未定义。另可同时报告可判定值 yes / (yes + no)，分母为零仍未定义，并明确它排除了 unknown，不能与以上范围混称。参照不可判定的行应记 unknown 或单列不适用，取决于指标定义；冻结前固定，不把不适用自动当模型错误。缺失的、失败或截断的调用必须单列；如果将来讨论计划集极端情况，需另列明确假设和分母，不得把它称为上述已完成集范围。

例如计划 6 条，完成 3 条（yes/no/unknown 各 1）、截断/失败/未运行各 1：完成集范围为 1/3–2/3，已判定 1/2；都不能说成计划集 6 条的成功率。

## 三态组及限制

每个完整三态组先分别标旧日实际结论、新日实际结论及缺日期回复是否失败。旧日与新日都正确的前提按照上述三值 AND 汇总；缺日期失败也保留 yes/no/unknown，得到 3 × 3 表。按此完整报告组数、两日均正确且缺日期失败数、前提或缺日期判断未知数，并额外列排除的未运行、截断及参照不足；筛选后不能推断模型内部机制，也不能当独立规则数。整答及版本引用可形成更严格的另一个前提，必须命名并独立报告，不覆盖原来的实际日内容口径。

## 核验范围

[聚合沙箱](../../../scripts/answer_change_scoring_sandbox.py)只接收调用方提供的三态标签；[CPU 测试](../../../tests/test_answer_change_scoring_sandbox.py)覆盖不完整调用、零分母、unknown 传播和三态表。它不是多规则运行器，不读取既有真实回答，不能保证人类标注一致或评审独立；正式采用之前仍须固定评审手册、引用判定、参考可判定性与文件接口。真实复核与来源用途尚未落实，扩样尚未决定。
