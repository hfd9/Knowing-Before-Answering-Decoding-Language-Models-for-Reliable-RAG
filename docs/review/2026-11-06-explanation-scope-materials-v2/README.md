## 材料和主比较

每场景含目标单位T、另一单位O、两个字段f/g及三个不同值a/b/c，12场景复用一种句式；规则说明同一快照、每单位每字段单值、字段独立、记录可能分歧且无优先级。

| 条件 | 三条记录结构 | 作者侧理解 |
| --- | --- | --- |
| S | T.f=a、O.f=b、T.g=c | 给定记录中一条支持目标a；这是记录相对支持，不证明记录必然真实。 |
| I0 | O.f=a、O.g=b、T.g=c | 目标T.f缺记录，且三条赋值兼容。 |
| IU | O.f=a、O.f=b、T.g=c | 目标T.f仍缺记录，另一单位同字段出现两个不同赋值。 |
| CT | T.f=a、T.f=b、T.g=c | 同一目标字段有两条不兼容的记录，不应无依据选边。 |

12个I0/IU问题相同且仅一个文档槽改变；该槽中把第二条记录的字段g改为f，同时把同槽冗余字段名f改为g。实际12对的词/数字多重集、字符总数、真实token长度与token多重集相同；这不等于所有token位置相同，也不能排除字段位置、语义、注意力或其他机制。六种代码角色排列各两次，询问alpha/omega各六场景，目标编号较小/较大各六场景；字段两方向各有三次编号方向互换。

原主要指标仍是12对的J(IU)−J(I0)，J为有据保留目标未知且明确无据断言目标字段冲突；保留unknown及完整分母。没有新回答，也没有行为率或主指标估计。旧三条关注例未加入本材料；它们的无据冲突表述不能自动计为狭义J正例。

## 见证与语义限制

I0各保存两个完整赋值世界；IU对另一单位相互冲突的两条记录分别保留其一，每个修复各给出两个不同T.f，合计四个见证；CT分别保留两个目标冲突记录之一，给出两个修复。S保存一个与记录兼容的世界。修复只是可行见证，不证明列出的值穷尽所有可能，也不假设两个冲突记录恰有一个为真。验证程序检查见证满足保留的记录且被移除的冲突记录与该世界不一致。

共享规则说记录可能有误或分歧，因此S的“有据”按**所给记录支持**解释，不是对世界真实值的认证。明确字段和单一模板可能使任务简单；12场景只改变符号、字段方向和槽位，不能当成12类自然任务。无冲突解释、目标值与整段解释支持仍需分别判断。作者已知条件和项目历史；[作者侧解释](author-interpretation.json)是按生成模板及逐条解析形成的48条条件解释，不是独立语义金标签或盲审。
