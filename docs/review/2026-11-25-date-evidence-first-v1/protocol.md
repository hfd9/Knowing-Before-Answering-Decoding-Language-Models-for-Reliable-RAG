# 先定位证据的适用日期抽取协议

## 开发材料

使用上一轮两条 Regulation Z 条款的原 E1–E4 和原六格案情。E1–E3 是已归档的原文摘录，E4 是有出处的人工范围摘要。每条款围绕两版门槛各补一组 `门槛−1`、`门槛`、`门槛+1` 的缺日期案情。再在一般金额规则上加入一个明确不适用案例和一个适用范围证据不足案例。原六格继续分别计数，边界控制和范围控制单列。

## 定位、抽取与求值

先用同一冻结模型在四份证据及无可用依据中定位比较原文、范围、较早与较晚版本。各项使用短候选字母的下一 token 分数。选择最高分候选，每个规则的定位结果跨案情共享。随后从选中的比较原文抽取 `>` 或 `<=`，并用选中的范围证据及该格的 F1 判定满足、不满足或资料不足。案情 F1 是题面指定的事实出处。程序从已定位的不同版本段落和 F1 规范化金额和日期，保留各字段的来源。控制事件从 F1 的可行日期句中提取，并在已定位的比较原文中核对。一份题面要求两段带起止日的版本、完整美元整数及 F1 的两个相邻可行日期。程序继续使用原确定性求值内核。

模型为固定 Qwen2.5-3B-Instruct，CPU FP32、SDPA、16 线程、每批最多 4 个选择提示。模型选择通过前向的末位 logits 完成，没有自回归生成。封存输入 token、每个候选的原始分数、任务身份及批次用时。人工参照仅用于评分及门槛判断。

## 验收与留出

开发通过要求原六格、两规则各两年度门槛的边界案情、范围拒答控制均严格通过。严格通过同时要求比较符、事件、范围、案情金额和日期、版本区间和金额、各角色证据与参照一致，以及按日结论和证据、动作、追问事件或未解决原因一致。已知日期可能掩盖错误的案情可行范围，因此字段也独立核查。

只在开发及封存重放通过后冻结实现、提示、评分、开发产物哈希和模型环境。随后再选取一条未见条款，所有案情变体使用同一对版本。保留一个同答、一个异答的缺日期案情，二者各设两个明确日期控制。分别报告同答多问、异答错误唯一答案和明确日期正确有据。新条款的失败先定位，单条规则的通过用于决定是否值得扩大样本。开发和留出均使用有出处的真实规则短摘与作者构造案情，范围证据若为摘要或日期区间经编排，会在对应材料标明。
