## 1. 已制作的三类材料

每个既有底题沿用原问题、第3–5槽、实体、字段及条件；第1/2槽使用原A/B表达交叉组合。每状态两种顺序，共6底题×3状态×2顺序＝**36条新组合、180个文档槽**。输入ID使用`rep_`前缀，避免与旧36条混淆；没有新底题。[完整材料](materials.json)、[知情作者参照](author-review.json)和[24个状态对照](pair-metrics.json)均为本轮构造；并未计算这些新输入的probe读出。

| 草案状态 | 第1、2槽内容 | 预期依据及范围 |
| --- | --- | --- |
| S：同值重复 | 两种措辞都描述相同对象、条件、字段和同一个目标值 | 作者知情判断为充分；两槽均提供相同值，并非两个独立来源的真实性认证。 |
| C：不同值重复 | 第1槽给原值，第2槽采用另一措辞但给不同值 | 作者知情判断为冲突；依第3槽的唯一性和无优先规则，不能以日常世界真值替代输入规则。 |
| I：缺证重复 | 两种措辞都列同一目标对象与负责人等信息，不提供所问字段值 | 作者知情判断为不足；两槽及第3–5槽需共同审核，不以目标字符串缺失当作充分证明。 |

以01题A顺序为例：S的两槽均给Tovan周五的north studio，C第2槽改为east studio，I两槽仅列仪器和负责人。第3槽规定每台仪器一个房间、无优先副本；完整原文和其他5题见材料及参照。原03题“both quays”指代边界仍在，06题dry/cold冲突依赖第3槽明确不同类别名称为不同类；二者未通过独立语义认证。

同底题同顺序的S→C只改变第2槽；S→I同时改变第1、2槽。S/I的A、B实际上交换两种措辞在第1、2槽的位置，**同时改变文本位置**；C的两顺序还涉及原值及异值与措辞的绑定，不是单纯原文交换。因此不能将它们称作只改变表述而其他一切不变，亦不能从一个差值识别单一机制。

## 2. 语义、长度和文本差异的实际核查

我已逐条读取36个问题、180个最终槽位及对应的知情作者参照。I的候选取值只用于解释为何唯一值未确定，没有加入输入；06使用明示类别规则，03保留指代歧义。这是已知旧probe结果的作者式判断，不是新独立评审，也不能保证审阅者不遗漏推断。参照文件逐条附五槽原文，以便未来评审；180处逐字引用检查只确认引用属于最终输入，不证明蕴含、缺证或表达等价。

使用本机Qwen2.5-3B-Instruct真实tokenizer及既有P0 chat完整模板渲染，36个输入为217–234 token。每种状态12个输入来自6底题的两种顺序，不是12个独立底题。

| 同底题、同顺序比较 | 文档变动 | 完整提示token差（右−左） | 槽1/2词集合Jaccard范围 |
| --- | --- | --- | --- |
| S→C，12对 | 仅槽2的值变化 | 10对相等，2对C多1 token | S：0.467–0.667；C：0.353–0.538 |
| S→I，12对 | 槽1、2均改变，值不再出现 | 0对相等；I比S短1–11 token | I：0.500–0.615 |

词集合指标使用小写ASCII字母/数字段，去重后计算交集/并集，不是模型token或语义相似度。与旧材料相比，三类范围有部分重叠；但**12/12个S→C对的C重合度仍低于S**，因此重复结构的词汇重合并未真正匹配，仍可能为状态提供线索。I和C的长度也不等：按本批逐底题同顺序计算，I比C短1–11 token。当前草案不能称为等长度或词汇匹配的充分控制，也不能证明未来probe响应的单一原因。

[生成器](build_draft.py)绑定原材料和本机tokenizer哈希，保存所有完整提示、token ID哈希和[逐对差异](pair-metrics.json)；独立[验证器](verify_draft.py)不调用生成器，重渲染全部36条P0 prompt并核对token身份、180处引用、24对槽位及相似度；[输出](independent-cpu-audit.json)通过。两条路径使用相同tokenizer和文本，不认证自然语言语义，也没有运行模型。生成器`--verify`可只读重建并核对所有草案字节，不应调用其他阶段生成模型输出。
