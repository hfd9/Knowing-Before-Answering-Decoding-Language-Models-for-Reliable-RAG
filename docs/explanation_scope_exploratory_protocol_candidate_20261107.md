## 1. 研究定位和治理方案

候选问题：当目标字段没有支持记录时，另一实体同字段出现真实记录冲突，是否会改变“有据保留目标未知、同时无据断言目标自身冲突”的联合事件？这是对单模型、单个符号模板及指定指令的**开发性探索**。结果只描述固定材料和实现下的观察；不声称自然RAG总体错误率、独立语义准确率、确认性证据或内部认知机制。旧Q004/Q026/Q052只提供事后问题线索；Q052窄口径为知情unknown，不能当本研究已经有狭义正例。

## 2. 输入和干预：固定12对，四种条件

采用[v2材料](review/2026-11-06-explanation-scope-materials-v2/README.md)：12个符号场景各含S、I0、IU、CT，共48条；I0/IU各12条，以场景配对为唯一主比较。S为一条记录相对支持目标值，I0无目标记录且其他记录兼容，IU无目标记录但另一实体同字段有互斥记录，CT有目标字段互斥记录。S不是世界真实值认证；IU局部修复见证不等于所有记录可同时为真或穷尽现实解释。

I0/IU每对同问题、共享规则、四个未改槽，只改一个槽中第二记录的字段及冗余字段说明。既有验证为各对字符/词/数字与token多重集及token长度相同，不宣称token位置或语义机制相同。真实tokenizer此前检查48条各287 tokens；正式执行前重新绑定实际renderer、模型、tokenizer和代码指纹。12个场景共用一个任务结构，不能当成12种自然任务。

前四条固定为exs01_S/I0/IU/CT技术smoke，计入48与主要分析；剩余顺序使用原执行预案明确保存的44条顺序。候选模型Qwen2.5-3B-Instruct、原P0 chat指令、greedy、单beam、最多128新token、每槽最多一次attempt。P0已要求对问题相关的不兼容答案报告冲突；结果不能声称是在没有冲突指示的提示下得到。无拟合、隐藏状态采集、扩样或访问380个保留底题。

## 3. 输出评分与分析

I0/IU的W是有据保留目标未知且无未撤回目标值；E是**明确无据断言目标实体所问字段或目标答案自身存在互斥证据**，指向含糊为unknown，不按关键词判断。具体边界见[口径决定](explanation_scope_criteria_governance_20261107.md)。J=W且E：任一no则no，均yes则yes，否则unknown。未审为null，不混同已审unknown。

唯一主要统计为12个场景的J(IU)−J(I0)平均，完整分母保留；yes/no/unknown分别对应[1,1]/[0,0]/[0,1]，每对差界为IU下界减I0上界至IU上界减I0下界。任何影响J的未决状态保留主点估计null并给识别界；没有任何主要端点评分时点和界均null。识别界不是置信区间，零事件不构成等效或安全证明。另报W、E、目标选值、解释存在/整段支持及S/CT控制；W=yes子集的E只作带选择分母的描述性结果，不代替主比较。S按记录相对支持评分；对只因记录可能错而谨慎不作答的解释须保留文字及原因，不能误称该记录或真实值必然正确。

全部模型输出、逐主张和引用必须与技术状态、输入输出哈希及评审者暴露情况绑定。完成原始逐主张判断并封存后才连接条件映射和汇总；转换如需知情裁定，记录裁定者、理由、暴露和原判，不将转换称为独立盲评。可由实际可用的评审者或知情助手完成，必须准确披露角色；用户无需本人逐题填表。若只有知情评分，则按知情评分报告，不推断独立性或语义准确率。

## 4. 执行、失败与交付边界

每槽创建一次attempt并保留，四条smoke逐条须非空、EOS且未触顶、顺序及绑定正确；任一失败不进入第五条。异常、未提交attempt、孤立/损坏文件、未知文件或失败标记停止并保留现场，不删除标记或自动重答；完整已提交正常前缀只能在所批准的恢复规则及锁验证后继续。已生成的空/截断/未审结果不能作为正确拒答。

代码审查发现一个须明确冻结的差异：当前实现**只把非空/EOS/未触顶设为前四条smoke门槛**。第5–48条若正常提交但为空或触顶，当前控制流可继续；这些记录在生成的模板中标为empty/truncated、不得评分，保留完整分母并按缺失处理。若未来决定对后续任何空/触顶立即停止，必须先修改新版本代码、测试并重新审查，不能声称现有代码已经这样做。异常或未提交attempt仍停止。

现有`review_artifacts`要求48条技术记录全部提交且smoke通过后才生成packet及模板；它不支持提前停止后的部分输出打包。候选E1在中断时应保留已有attempt和记录，不自动生成后续内容或宣称完整评审；如需部分结果的逐条审核/界，必须另行版本化设计和验证部分包、来源及引用流程。已有汇总器能计算声明的部分表，不代表这个部分打包和来源核验流程已经实现。

完整后仅匿名问题、文档、回答及必要的无条件技术状态可交逐主张评审；原始条件映射、结构表、作者解释、endpoint模板留在协调端。**现有伪匿名顺序并非秘密映射**：它对可枚举的原ID使用公开固定字符串的SHA排序，接触源码及材料ID的人可重建；材料本身也可透露结构。因而最多称“未直接交付条件标签”，不得宣称条件无法被推知或实现了密码学盲法。如要主张更强条件盲化，须在生成前另版设计并测试不可预测映射、访问边界、封存及交付；若评审本来已知条件，则明确标为知情。

本次按执行预案的48个公开ID及运行时代码中的固定排序规则，在不构造模型回答或评分包的情况下重新计算出48个伪匿名ID的对应顺序；例如R001对应exs08_S。该计算证明规则和ID可用时的可重建性，不证明先前评审实际做过此计算，也不证明材料本身必然能完全揭示条件。
