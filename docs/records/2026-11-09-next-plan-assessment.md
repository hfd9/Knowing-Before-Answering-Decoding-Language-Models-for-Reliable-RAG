# FaithEval 后续计划评价

日期：2026-11-09。用户询问来源条款、已有文档筛查独立重放、封存碰撞处理及研究去留的四步计划是否合理。本轮只评价计划，不表示用户已要求执行其中的操作。

计划顺序和停止条件合理，和[既有停止点](../review/2026-11-09-faitheval-dependency-gate-v1/README.md)一致。评价时核对了 FaithEval [unanswerable 数据卡](https://huggingface.co/datasets/Salesforce/FaithEval-unanswerable-v1.0)、[inconsistent 数据卡](https://huggingface.co/datasets/Salesforce/FaithEval-inconsistent-v1.0)及[代码仓库](https://github.com/SalesforceAIResearch/FaithEval)；代码许可不能替代对数据及上游文本具体用途的核查。本轮没有完成新的分来源许可结论。

建议执行时明确：

1. 分来源、固定版本及具体行为区分临时读取、本地保存、改写和公开。依用户提出的严格停止条件，关键用途不清即停；不因研究用途声明自动认定其他用途获准。
2. 对原785个连接和2,270个旧长文档的完整复验需使用同一纳入范围和标准，比较各项聚合结果、短文本排除及失败和重试。若许可导致排除任何原纳入来源，仅能记为不同分母的受限子集检查，不能声称完整重放通过。独立实现须说明数据读取、规范化和聚合哪些部分独立、哪些仍共用。
3. 现有约定下，380题正文封存，碰撞未知；控制程序只输出聚合并不自动构成读取许可，也不能自动确保未来确认集未受影响。须先核对实际规则并明确允许，审视汇总结果及其对选材的影响；否则不读取、不宣称无碰撞。
4. 前述条件成立后才考虑五文档构造、语义审核及重新比较近邻；来源或处理方式不能成立时收缩或停止。

本轮仅查看已有记录及公开页面，未重新读取候选或封存正文、重放真实筛查、构造输入或标签、起草实验协议、运行模型或 GPU。原门禁 false、正式独立批准 0、原拟合预算 0、正式标签 null、380 题正文封存不变。
