## 目标与背景

用户希望保留“缺失的信息是否改变答案”的研究问题，冻结现有抽取器，通过约两周的分阶段对照决定继续法规、转向版本检索，或探索软件版本问答。该周期为计划估计，取决于模型、材料和独立复核资源，并非完成承诺。上一轮[角色冲突诊断](2026-11-25-role-conflict-diagnostic.md)表明阻断策略对已暴露 36 格仅保留 6 格，不采用。此前[两条规则留出](2026-11-25-role-assignment-and-natural-v2.md)中冻结联合定位严格 24/36；事后纠正 36/36 不是独立结果。论文主实验未启动。

## 实际操作

制定以下工作顺序及停止条件；本轮未选择新规则、构造题目、确定模型、创建实验数据、执行生成或运行评测。后续各阶段完成后另行记录，先准备和核验再采集。

## 后续执行计划

### 0. 建立可复现的冻结基线与评分草案

1. 盘点并固定当前联合角色定位抽取器、求值器和既有 3B 对照的准确提交、入口、依赖、提示、模型文件与参数；记录哈希及已有问题。此前所有看过输出或错误的规则均为开发集。冻结仅用于后续比较，不将事后冲突阻断或人工纠正包装为已验证方法。
2. 在开发材料上先编写并检查评分手册：明确日期区间、相关事件、版本有效性、范围和例外；区分事实结论、用户动作与证据充分性。保留完整自然语言输出、原始引用、格式错误、截断与无法评分。先区分可判定、证据不足、版本绑定错误和其他阅读错误，不将它们统称谨慎。
3. 选定实际可用的较强指令模型、调用方式、数据发送许可、预算和代价；记录模型标识、访问日期、解码与失败处理。若没有可用模型或独立复核，不宣称比较已经就绪。GPU 按既有约定由用户执行；助手先完成代码、CPU 检查、时间估算和失败处置。
4. 重核法规及软件近邻原文、公开材料许可和适用范围；构造材料时固定原始来源和版本，不假定可再发布。旧门禁、预算及封存不因本计划自动改变。

### 1. 两条规则的开发试运行：评分与接口

在上述草案就绪后，选两条以前未用于项目分析的规则，各构造一对金额不同但材料和缺失日期相同的同答／异答题；固定可行日期区间，覆盖该区间所有相关版本，逐版核对范围、边界与例外。每对补日期已知对照，并对需要澄清的回答提供一致的日期回复，检查第二轮最终结果。由能够独立判断法规的人复核原文和参照；无法获得时只能作为作者知情开发试运行，不能称独立法律复核。

同题比较强模型直接回答与同一模型逐版结论及引文后再回应，保留原输出、调用与成本。可先使用已有开发规则演练评分，避免在评分手册尚不稳定时消耗候选。试运行的两条规则在看过输出后即归开发集，不进入后续留出。重点查条件式回答是否被误判、证据是否支持各结论、补日期后是否正确及提示／预算是否可用；不据此作泛化或论文结论。

### 2. 冻结后选择整条规则：第一周目标

根据试运行修正材料模板、提示、评分手册和规则级汇总方法；固定版本及哈希，再选择目标约 8–12 条整条未见规则，作为探索性去留样本而非统计功效保证。记录选取流程、排除原因和来源，避免根据模型表现筛规则；如可复核条款或人力不足，报告实际数量及限制，不虚称独立样本。

每条规则尽可能包括：(a) 日期缺失、证据完整且各可行版本同答；(b) 日期缺失、证据完整但不同版本异答；(c) 日期明确但当前上下文缺对应有效版本、固定语料库存在该版本。明确用户需要唯一结论还是接受条件式回复。前两种尽量以仅改案情数值的配对形成；补日期已知、范围及比较符边界对照，逐版留存作者参照、来源和核验。独立复核者对照原文确认版本日期、适用范围、例外与结论；记录身份角色、暴露和分歧，未解决项保留 unknown，不强行纳入分母。

状态 (c) 必须提供真实检索工具及固定语料库时，才能将检索作为预期动作；封闭材料情境下应承认证据不足，不因没有工具而判检索失败。完整证据下可另人为移除版本测试证据不足识别，须与实际检索分开。

### 3. 同题对照：第二周目标

在相同规则、题目、完整原文和版本元数据下比较：(1) 强模型直接回答；(2) 同一强模型先逐版本给结论与证据再决策；(3) 冻结抽取加求值。已有 3B 结果只作历史参照；若材料或提示不同，不作同题效果比较。人工字段加求值仅作知情诊断上限。预先固定每路线的输出契约、最大 token、调用次数与异常处理；保持预算上限足以完成任务，分别报告实际 token、耗时、成本和截断，避免统一低上限偏置逐版路线。

先做全证据阅读，再在独立会话用相同题目和实际检索结果测试；固定语料、索引、版本元数据、检索预算、top-k 与日志，避免完整证据通过会话历史泄漏到检索阶段。记录检索后覆盖、缺失哪版和最终行为；不把人为删除证据冒称实际检索。若需公平比较主动找反例，另预先固定同预算普通 top-k 与二次检索规则；这属于结果支持后的下一阶段，不预称本轮已实施。

### 4. 评分与汇报

按规则汇总配对，报告每条规则及总数、未知、无效、失败和缺失分母；同规则改写不视作独立规则。主要列：

| 指标 | 预定解释 |
| --- | --- |
| 唯一结论判断成对正确率 | 同答／异答对中，两题均正确判断限定日期范围内能否给唯一结论；格式错误和未知单列，主要口径不把未知当正确。 |
| 回复有效性成对正确率 | 同答题给有据正确结论；异答题给正确、完整的条件式结果，或在要求唯一结论时提出可区分版本的有效日期追问；按预先指定的用户要求评分。 |
| 错误唯一答案率 | 在异答且日期未知的题中，无条件给出单一结论的比例，报告分子与全部异答题分母；另区分事实值错误及证据不足下不当确定。 |
| 无谓追问率 | 在证据完整、同答且任务允许直接回答的题中，不必要地要求日期的比例。 |
| 逐版本结论与引用 | 对每个相关版本报告结论正确、引用严格匹配及引用充分性；引用语义由对路线和系统身份盲化的复核者评定，记录分歧和未知。 |
| 补日期后的最终正确率 | 在发生追问并收到有效日期的预设轨迹中，报告最终正确且有据的比例及分母；另报覆盖率，避免只统计易追问题。 |
| 读取／检索失败 | 证据未覆盖、已有证据却错绑、规则应用错误、格式或工具失败分别统计；保留原始输出。 |

评分应接受准确完整的条件式回答，不把它当错误唯一答案；若任务明确要求唯一结论，则另评是否提出有效追问。各指标区分用户明确日期与系统所缺证据。按规则展示配对，必要时仅报告探索性不确定区间；在如此小样本下不声称精确总体效果。

### 5. 预设去留与阻塞处理

- 全证据下强模型多条规则混淆同答／异答，而逐版路线稳定改善：继续研究逐版比较；再按同题错误和成本判断显式求值器是否额外解决问题。先核对参照及评分后再决定扩大验证。
- 全证据表现较好、实际检索导致漏掉改变结论的版本和错误唯一答案：优先设计相同预算的普通检索与主动寻找反例版本对照，预先定义反例版本召回和最终错误唯一率；不把一般时间覆盖直接等同于反例覆盖。
- 强模型已处理得较好，或法规来源／独立复核持续无法落实：先做软件版本可行性，不直接宣布转题。核对 [QAMR](https://arxiv.org/html/2601.02345) 最新版默认及 [pandas 2.0 变更](https://pandas.pydata.org/docs/whatsnew/v2.0.0.html)；固定 Python、pandas、依赖、完整输入与环境，实跑跨版本同答／异答对，保存实际输出、版本和来源。随后再核对软件近邻与材料多样性，决定是否转向。
- 若强模型、可复核材料、实际检索或资源缺一，则收缩至可以可靠完成的开发或材料核查，明确未完成项；不得用作者知情判断冒充独立复核，也不以时间到期替代证据。
