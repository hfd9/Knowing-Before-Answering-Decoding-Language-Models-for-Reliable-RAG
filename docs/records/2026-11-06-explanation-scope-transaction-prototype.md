# 2026-11-06：解释行为采集事务的临时目录原型

用户询问后续工作并要求继续；按已知偏好由助手自主实施，不要求用户逐项人工审核。本轮开始工作区干净，父提交29ff50f3ed1c329d23f7c9ced28d578ba1f9332a。基于原有固定48顺序和合成账本，新增[临时目录真实文件事务原型](../../scripts/explanation_scope_transaction_prototype.py)，详细范围见[说明](../explanation_scope_transaction_prototype.md)。

原型仅允许系统临时目录的已有子目录及synthetic manifest，使用非阻塞POSIX锁、带计划哈希的独占attempt、文件及目录fsync、同目录pending与os.replace，并保留异常文件；无真实采集入口、模型加载、GPU或自动删除恢复。状态检查复用原合成账本，额外重算合成文本哈希并核对虚构token数，但不解码token、不认证EOS或真实prompt。

实现过程中发现：仅禁止再次创建attempt还不足以阻止另一锁会话向旧未提交标记补写。已收紧为只能由创建标记的当前进程及当前锁会话提交，解锁、进程退出或fork均撤销权限；新增测试验证旧标记保留且不能自动补写。这是设计时发现并修复的问题，无真实实验受影响。

实际20项新CPU测试4.731秒、exit0；含跨进程锁、进程直接退出于标记后/替换前/替换后目录同步前、提交后退出、pending保留、篡改与不完整初始化停止、空输出及触顶smoke、未通过smoke不能提交第五项、fork和锁会话所有权、48合成记录上限、临时目录限制及符号链接拒绝。替换后同步前退出只验证当前系统可见性，不证明断电或网络文件系统持久性。测试全部为临时目录合成数据，并随测试清理，不是实际run/回答。

原合成账本11项0.018秒、有限模型2项0.207秒均通过；材料生成器verify和旧CLI只读verify实际exit0。此前材料及CPU预案记录的17+12=29文件哈希一致；旧CLI核验72来源、12拟合封存及四接收快照保持。无新模型回答、权重加载、前向、拟合、GPU或380访问；不修改已封存材料、评分契约或旧run。

此原型不是完整真实采集器：真实prompt与token绑定及解码、EOS、模型/权重指纹、GPU设备检查、真实缓存、故障恢复及评分连接均待另做；不能因合成测试通过而自动放行采集。独立批准0、formal_gate/GPU=false、原拟合预算0、正式标签null、380封存保持。[机器记录](2026-11-06-explanation-scope-transaction-prototype.json)保存文件哈希与测试边界。按长期授权正常提交推送，实际提交及远端哈希以Git和本轮回复为准。
