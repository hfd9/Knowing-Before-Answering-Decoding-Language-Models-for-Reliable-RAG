# 解释行为：受关闭门禁约束的生产路径实现

日期：2026-11-06。[生产路径](../scripts/explanation_scope_production.py)已编写，事务和调用流程以临时目录、合成token及模拟设备/模型测试；**当前冻结计划持续禁止创建真实run、加载模型或启动采集，真实GPU路径尚未执行或验证**。

生产入口 `collect(runtime)` 首先调用现有关闭门禁；直接打开生产目录、构造生产写入器和使用共享事务内核的非合成模式也先调用门禁。当前 `Runtime.assert_collection_disabled()` 必然拒绝，且原计划加载器要求相关guard保持false，因此本代码不是一个可通过修改命令行参数启动的实验入口。若未来形成新的审查通过的执行协议，必须明确修改并重验门禁、计划与执行实现；历史草案不授予采集权限。

门禁后的代码设计如下：核对封存的48条输入指纹文件、实际重建的输入、tokenizer元数据和13项历史实现哈希；固定项目run目录使用同一个文件事务内核。仅本次成功创建的空目录可以初始化；已存在但未完成初始化的目录不会自动修复。锁、attempt、记录、smoke及文件类型均复核，正常提交前缀可恢复；未提交attempt、孤立/损坏记录、未知文件、替换失败产生的pending文件或失败smoke均停止并保留现场。持锁期间按固定顺序检查prompt和token，在生成前独占创建attempt，生成后校验前缀/输入未变、token、EOS、长度和解码后原子提交；四条技术smoke计入48并通过后才能继续。模型报错或验证失败时attempt留存，不自动重答。

生成前重新流式核对七个模型文件（包括两个权重分片）的SHA-256，先用 `nvidia-smi` 查询计算进程，再检查单个可见CUDA设备及bf16能力；检查成功后加载本地模型，使用固定greedy参数、单beam及128 token上限。设备空闲检查是瞬时观察而非设备预留，模型文件读取与加载之间仍存在变化窗口；这些检查不构成独立的来源认证。已完整提交的缓存只做验证，不重新加载模型。

## 测试范围和限制

临时集成测试**显式模拟放行条件、GPU检查和模型加载**，且将测试manifest标记为synthetic；生成器是CPU固定token桩。它实际执行生产 `collect` 的控制流、生产写入器、同一事务内核和真实tokenizer，并测试48条、跨进程在attempt后退出、锁竞争、替换失败、损坏、生成异常和smoke失败。它不是实际GPU/Transformers推理，也不能证实真实模型兼容、CUDA同步、设备独占、输出真实来源或断电持久性。本轮仅流式读取真实权重做SHA校验，没有加载权重或运行前向。

formal_gate=false、gpu_launch_ready=false、独立批准0、拟合预算0、正式标签null及380题封存保持；实际真实run和新回答均为0。技术实现及合成测试通过不等于正式授权或GPU就绪。
